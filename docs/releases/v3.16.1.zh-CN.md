# v3.16.1 — 运行观测、来源超时与保存冲突修复

[English](v3.16.1.md) | **简体中文**

发布状态：准备中。最终源码、实际检查及发布结果将在[实施与验收记录](../development/runtime-source-save-fixes.zh-CN.md)维护；本页不宣称发布门禁已经通过。

- 运行观测在 turn 启动时保留代理身份，使子代理请求与完成共享同一生命周期记录，不再留下虚假的运行中主回合；按已观测结束时间核对迟到终态批次（[#197](https://github.com/fbincon/claude-code-statusline/issues/197)）。
- 保留命令源的失败超时、执行诊断和错误观测，不再把 deadline 到期变为 `cancelled/no_consumers`；延迟结算确认成功或需暂停的失败后，核对暂记的自动反馈（[#195](https://github.com/fbincon/claude-code-statusline/issues/195)）。
- 将明确目标的 `profile_conflict` 识别为确定拒绝，双编辑器直接打开普通冲突审阅，保留草稿／历史及胜出方已保存配置（[#196](https://github.com/fbincon/claude-code-statusline/issues/196)）。

显示 schema 17、编辑器协议 31及既有来源／runtime／存储格式保持兼容。升级后重新运行 `claude-statusline install`，并重启 Claude Code 加载匹配的 runtime Mod。不会把不完整的历史观测改称完整。

发布验收保留八个安装目标、32 项 Node、十六个固定宿主、全部当前 313 项 Native 容量案例及完整十二语言就绪。Client props、外层 Pane 和 Client 绘制继续使用独立限制和宿主侧恢复。已批准的真实交互 runtime 补充验收在全部付费尝试／重试间共享 10 美元预算；实际费用与结果仅在执行后记录。

只接受 [#96 六项既有缺口](https://github.com/fbincon/claude-code-statusline/issues/96)，它们仍未验证。发布完成后本机新发现只提 issue，保留 v3.16.1，本任务不再补发其他修补版。

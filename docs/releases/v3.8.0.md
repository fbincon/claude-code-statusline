# v3.8.0 — Git policy, consistent previews and explicit package management

Review a persistent installation from the no-argument entry, then manage upgrades, rollback and recovery with explicit CLI commands.

- Git observations share one bounded policy, disable fsmonitor and implicit bare discovery, and preserve ownership checks. Standard Git LFS, supported external git-crypt and user-managed filters retain their semantics; unsupported repository filters report unavailable rather than a false clean state.
- Setup, configure and slash-launched external editors share session color detection. A verified Windows VT console defaults to 256 colors when no explicit preference exists. No-color and monochrome choices remain authoritative; console modes are restored on exit. Saved appearance, production statusline output and native editor themes retain their behavior.
- Running `claude-statusline` or the npx package entry in an interactive terminal reviews the exact package, prefix, executable paths and Claude configuration directory before a global npm installation. The verified persistent entry continues setup. Noninteractive no-argument calls exit with guidance; conflicting versions and ambiguous prefixes require an explicit choice.
- `update --check` inspects metadata and compatibility only on request. `update`, `rollback`, `recover --package` and separate `recover --restore-config BACKUP_ID` verify identity/integrity and compatibility, retain transaction and recovery material, and distinguish package replacement from integration completion. Scripted package changes require an exact version, explicit prefix and `--yes`.
- Automatic transitions are verified from the published v3.7.0 archive. A new compatibility descriptor supports later releases; earlier versions use documented manual recovery. Current display choices, profiles, bindings, independent opt-outs and source authorization remain protected by revision and ownership checks.

Node 22/24, existing supported platforms and all six languages remain supported. Display schema 13, editor protocol 21 and existing source/runtime protocols are unchanged. No version-management page is added to either editor.

See [first installation](../SETUP.md), [package management and recovery](../PACKAGE_MANAGEMENT.md), [CLI reference](../reference/cli.md) and [delivery evidence](../development/m8-m9-delivery.md). Publication requires final PR/main/tag automation and channel verification. The [version-specific approval](approvals/v3.8.0.json) accepts only the same six unverified #96 gaps; no new failed or missing automated gate is waived.

通过无参数入口审核持久安装，再使用明确的 CLI 命令升级、回退和恢复。

- Git 观测采用统一有界策略，禁用 fsmonitor 和隐式裸仓库发现，保留所有权检查。标准 Git LFS、受支持的外部 git-crypt 及用户管理过滤器保留原语义；不支持的仓库过滤器明确报告不可用，不伪装成干净状态。
- setup、configure 和 slash 启动的外部编辑器共用会话色彩判断。没有显式偏好时，已验证的 Windows VT 控制台默认使用 256 色；无色及单色选择优先，退出恢复控制台模式。保存的外观、生产状态栏输出和原生编辑器主题保留原行为。
- 在交互终端运行 `claude-statusline` 或 npx 包入口，会在全局 npm 安装前审核精确包、prefix、程序路径及 Claude 配置目录；验证后的持久入口继续 setup。无参数非交互调用立即给出指引并退出，版本冲突和多 prefix 歧义需要明确选择。
- `update --check` 仅在请求时检查元数据和兼容性。`update`、`rollback`、`recover --package` 及独立的 `recover --restore-config BACKUP_ID` 验证身份、完整性和兼容性，保留事务及恢复材料，并区分包替换与集成完成。脚本包变更必须提供精确版本、明确 prefix 和 `--yes`。
- 自动转换从已发布的 v3.7.0 产物验证，新兼容声明供后续版本接入；更早版本使用文档中的手动恢复。修订及所有权检查保护当前显示选择、方案、绑定、独立关闭选项和来源授权。

继续支持 Node 22／24、既有平台及六语言。显示 schema 13、编辑器协议 21 和既有来源／runtime 协议保持不变；两个编辑器均不新增版本管理页面。

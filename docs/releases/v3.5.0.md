# v3.5.0 — Guided setup and complete display schemes

Connect first-use checks, scheme preview and explicit Claude integration with `claude-statusline setup`.

- Preview changes before committing; use read-only `setup --dry-run`, keep an existing display, or save a display before integration. Partial failures report completed stages and recovery instructions.
- Choose `daily-development`, `agent-focus` or `quota-watch` in either editor, save to the current target or save a named copy, and share single-profile JSON. The six existing presets and saved opt-outs are retained.
- Configure Powerline block padding, separator shape, independent start/end decorations and semantic/continuous/restarted colors. Explicit item colors and width/grapheme boundaries remain respected.
- Keep missing and expired quota observations distinct from zero. ASCII task/agent markers preserve state rather than using one generic icon.
- Use all six existing interface/output languages. Configuration stays local, and scheme selection does not enable collection or external capabilities.

Display schema advances to 9 and editor protocol to 16. Schemas 1–8 migrate in memory without writes; explicit save/install preserves pre-migration backups. Runtime 2, lifecycle 4, portable 1, UI preferences 1 and profile collection/export 1 remain unchanged. Reinstall matching frontend/backend resources when upgrading; restore a compatible backup when downgrading.

Install or upgrade the npm package, then run `claude-statusline setup` or the existing `install`/`doctor` commands. Restart Claude to verify the actual session display. Resource checks and sample previews do not establish live loading or human desktop acceptance. Node 22/24 and the existing platform boundaries are retained.

The [v3.5.0 maintainer decision](approvals/v3.5.0.json), approved on 2026-10-23, accepts only the six historical unverified observations in [#96](https://github.com/fbincon/claude-code-statusline/issues/96). New functional or automated failures remain blocking.

`claude-statusline setup` 将首次检查、方案预览与明确的 Claude 接入串联起来。

- 应用前审阅变更；支持只读 `setup --dry-run`、保留已有显示和接入前保存显示。部分失败准确报告已完成阶段与恢复步骤。
- 两种编辑器可选 `daily-development`、`agent-focus`、`quota-watch`，保存当前目标或另存命名副本，并通过单方案 JSON 分享。保留原六种预设及关闭偏好。
- Powerline 支持色块留白、受控分隔形状、独立首尾装饰和语义／跨行连续／逐行重置配色；保留逐项覆盖及宽度／字素边界。
- 缺失、过期额度与真实零保持区别；ASCII 任务／代理标记保留状态含义，不再统一成相同通用图标。
- 保留六语言界面与输出。配置保存在本地，选择方案不会启用采集或外部能力。

显示 schema 升至 9，编辑器协议升至 16。schema 1–8 在内存中迁移而不写入；明确保存／安装保留迁移前备份。运行协议 2、生命周期 4、portable 1、UI 偏好 1、方案集合／导出 1 不变。升级需重新安装匹配前后端资源；降级需恢复兼容备份。

安装或升级 npm 包后运行 `claude-statusline setup`，也可继续使用 `install`／`doctor`。重启 Claude 验证真实会话显示；资源检查与样例预览不代表实际加载或真人桌面验收。继续支持 Node 22/24，平台边界保持不变。

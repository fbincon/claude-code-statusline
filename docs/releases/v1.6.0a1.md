# v1.6.0a1: Live state and advanced metrics preview

This complete Phase 5 preview adds eleven opt-in items and an independent collector. **Latest stable remains v1.5.0. New runtime support stays in preview until affected real-session/platform acceptance is recorded.** The existing macOS Client input limitation remains open.

- Add verified run state, recently observed permission mode, active nested agents, structured checklist completion and last main tool outcome.
- Compare committed branch files/additions/deletions from merge-base(base, HEAD) to HEAD, with explicit/automatic base refs, commit-isolated caching and one 2-second deadline. No automatic fetch.
- Freeze ended subagent duration using reliable native or existing lifecycle-hook evidence, including when independent collection is off. Missing end evidence retains the status marker.
- Add host-observed latest-main-request TTFT and output rate including first-content wait, plus deduplicated cache-inclusive task tokens across verified agents and main wrap-up. Turn totals reconcile coverage without double counting.
- Passively observe official existing collector cost estimates. Missing data is unavailable, zero remains zero, and incomplete/unjoined subtotals carry an asterisk. Exporters and model prices are not changed.
- Independent runtime protocol v1, display schema v4 and configuration protocol v3. Both editors, CLI, wizard and deterministic previews share the catalog; v1/v2/v3 reads normalize in memory and actual saves back up before migration.

## Install or upgrade

Python 3.10–3.14; Linux/WSL, Windows and macOS. Runtime tested on Claude Code 2.1.289; older hosts retain basic functionality. Live collection defaults off in preview and stable, preserving its independent preference. Fresh preview editor entries are explicitly requested; existing choices persist.

~~~text
pipx install --force "https://github.com/fbincon/claude-code-statusline/releases/download/v1.6.0a1/claude_code_statusline-1.6.0a1-py3-none-any.whl"
claude-statusline install --live-metrics --native-editor --experimental-slash-tui
claude-statusline config enable run-state permission-mode active-agents task-progress last-tool branch-diff ttft output-rate prompt-input-tokens prompt-output-tokens prompt-cost
claude-statusline doctor
~~~

Restart Claude Code. Use install --no-live-metrics for persistent disablement. Set the branch base using config set branch-diff-base auto or REF. See [definitions](https://github.com/fbincon/claude-code-statusline/blob/v1.6.0a1/docs/DISPLAY_ITEMS.md), [runtime contracts](https://github.com/fbincon/claude-code-statusline/blob/v1.6.0a1/docs/development/live.md) and [migration/downgrade](https://github.com/fbincon/claude-code-statusline/blob/v1.6.0a1/docs/USER_GUIDE.md#version-compatibility).

## Validation and limitations

- Local Python: 552 tests, 544 passed and 8 expected platform skips. Official Mod tests: 41 native and 7 runtime; both TypeScript projects, generated contracts, strict runtime validation, Ruff and bilingual documentation passed.
- CI: 13 Python/build and 7 fixed Mod jobs: Linux 2.1.287/288/289, Windows/macOS 2.1.288/289. PR, merge and tag checks are release gates.
- Real isolated Linux x86_64/Python 3.14.4/Claude Code 2.1.289 probes verified single-agent and parallel requests, main wrap-up and repeatedly frozen ended-agent rows. Known source acceptance spending was USD 0.206195; every attempt/retry shares the original USD 10 ledger.
- Same-machine 50-sample legacy render P50/P95: 53.974/63.257 → 52.353/63.664 ms. Small fixtures and scheduling noise limit conclusions; lazy collection and previews have regression coverage.
- SDK/headless paths may omit prompt identity events. Only one completed existing lifecycle interval containing a main turn start can bind it, then explicit spawn identities resolve children. Overlapping/unfinished windows stay unowned; SDK live values may await end evidence. This never writes timer state.
- Permission snapshots expire after 15 seconds and are marked recent; settings defaults are not live mode. Timing needs real engine content. Cost stays unavailable without an existing applicable collector feed; no telemetry or price fallback is enabled.
- Windows/macOS runtime installation CI and Linux headless/PTY checks do not establish new human runtime interaction acceptance. Stable promotion remains gated; historical editor acceptance does not replace it.

Release assets must come from the fixed verified merge commit and pass independent inspection/rebuild/install, installed-wheel Linux 120×30/80×48 PTYs, draft SHA256/byte comparison, then public redownload/installation. Raw evidence is excluded from distributions.

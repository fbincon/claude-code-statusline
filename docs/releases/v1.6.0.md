# v1.6.0: Live state and advanced metrics

Stable v1.6.0 promotes the complete Phase 5 preview after the maintainer confirmed v1.6.0a1 acceptance on Linux, Windows and macOS on 2026-10-05. Exact OS, architecture, terminal and host versions were not supplied. The existing macOS Client input limitation remains documented. The historical [v1.6.0a1 preview](https://github.com/fbincon/claude-code-statusline/releases/tag/v1.6.0a1), its assets and prerelease status are preserved.

- Eleven opt-in items: run state, recently observed permission mode, active agents, structured task completion, last main tool, committed branch difference, host-observed TTFT/output rate and complete-task input/output tokens/cost.
- Committed branch comparisons use merge-base(base, HEAD), an explicit or automatic base and a shared 2-second deadline, without automatic fetch. Reliable lifecycle end evidence freezes ended-agent durations even when live collection is off.
- Verified request identities include reliably attributed nested agents and main wrap-up. Missing observations display `—`, real zero remains zero and partial subtotals carry `*`. Official existing cost observations are passive; exporters and model prices are unchanged.
- Python and both Mods are 1.6.0. Display schema v4, configuration protocol v3 and independent runtime protocol v1 retain the accepted a1 implementation. Reads of display v1/v2/v3 normalize in memory; actual saves back up and migrate. No display migration is needed from a1.

## Install or upgrade

Python 3.10–3.14; Linux/WSL, Windows and macOS. Fixed runtime validation uses Claude Code 2.1.289; older/unknown hosts retain compatible basic functionality and suspend unsupported integration. Stable editor entries default on for supported hosts, preserving recorded false. Live metrics remain independently off without a preference; both true and false persist across promotion.

~~~text
pipx install --force "https://github.com/fbincon/claude-code-statusline/releases/download/v1.6.0/claude_code_statusline-1.6.0-py3-none-any.whl"
claude-statusline install
claude-statusline doctor
~~~

Restart Claude Code. To opt into collection, run `claude-statusline install --live-metrics`, then select metrics in either editor or use:

~~~text
claude-statusline config enable run-state permission-mode active-agents task-progress last-tool branch-diff ttft output-rate prompt-input-tokens prompt-output-tokens prompt-cost
~~~

`install --no-live-metrics` saves an independent disabled choice. Set branch base with `config set branch-diff-base auto` or a ref. Before downgrading, use this newer package to disable live/native integration and restore a compatible pre-migration display backup. See [definitions](https://github.com/fbincon/claude-code-statusline/blob/v1.6.0/docs/DISPLAY_ITEMS.md), [runtime contracts](https://github.com/fbincon/claude-code-statusline/blob/v1.6.0/docs/development/live.md) and [migration/downgrade](https://github.com/fbincon/claude-code-statusline/blob/v1.6.0/docs/USER_GUIDE.md#version-compatibility).

## Validation and limitations

Local validation passed 553 Python tests (545 passed, eight expected platform skips), 41 native and eight runtime official Mod tests, both TypeScript projects, generated contracts, strict plugin validation, Ruff and bilingual documentation checks. Isolated core/native/runtime installation checks and five a1-to-stable upgrade combinations passed, preserving explicit choices and leaving display files unchanged. All 20 CI jobs (13 Python/build and seven fixed Mod jobs) must pass on PR, merge and tag. Assets are built from the fixed verified merge and must pass independent wheel/sdist inspection/rebuild/install, installed-wheel Linux 120×30/80×48 persistent advanced PTYs, draft/public SHA256 and byte comparisons, and isolated public wheel/sdist/fixed-tag URL installations. Raw reports are excluded from distributions.

The new three-platform maintainer confirmation is recorded separately from automated CI, Linux PTYs and the preview's real Linux 2.1.289 single-agent/parallel/main-wrap probes and frozen-duration evidence. Promotion changes versions/defaults and docs; captured runtime observations are revalidated without repeating paid calls. Every real attempt/retry retains the original USD 10 ledger (USD 0.216580 known plus USD 0.50 conservatively reserved before promotion).

SDK/headless paths may omit prompt identity events: only unique completed lifecycle intervals and explicit spawn ownership resolve those records. Overlapping or unfinished windows remain unowned; live values may await end evidence. Permission snapshots are marked recent and expire after 15 seconds. TTFT needs real host content, and cost stays unavailable without an existing applicable official collector feed. These limitations remain in stable v1.6.0.

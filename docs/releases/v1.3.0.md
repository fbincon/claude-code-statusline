# v1.3.0 — External TUI and in-session Client editors

This stable release promotes the v1.3.0a2 Client interaction after maintainer-confirmed human acceptance on Linux, Windows and macOS. Both editor entries now default on, with independent preferences and host compatibility handling.

- `/statusline-configure` opens the existing external terminal TUI. `/statusline-configure-native` opens Client inside the current Claude Code session. They install/disable independently and may remain open together; revision checks reject stale saves without overwriting newer configuration.
- External needs Claude Code 2.1.258+; Client needs 2.1.287+. Older or unrecognized hosts suspend only unsupported entries, retain enabled preferences and keep basic integration working, including when explicitly enabled. Plugin removal uses older-host-compatible official commands and verifies the result through listings. Rerun install after upgrading/downgrading. The standalone TUI, wizard and CLI remain available.
- Explicit flags override saved preferences, which override defaults. External disablement now saves schema-v1 false instead of deleting the file. Older absence follows the new enabled default; use the disable flag again to keep that entry off. User-disabled plugins remain disabled while their owned resources and backend binding update; only tool-recorded suspension restores automatically.
- Bilingual README and user-guide navigation now cover all configuration methods, combinations, preference files, keyboard controls, recovery, upgrade behavior and version boundaries. Client screenshots retain their a2 provenance.

## Install or upgrade

```text
pipx install --force "https://github.com/fbincon/claude-code-statusline/releases/download/v1.3.0/claude_code_statusline-1.3.0-py3-none-any.whl"
claude-statusline install
claude-statusline doctor
```

On Windows use `claude-statusline.exe`. Restart Claude Code in a trusted terminal afterward. Install does not open another terminal or an editor. To disable either entry, use `install --no-native-editor` or `install --no-experimental-slash-tui`; reenable with the corresponding positive flag. The historical external flag name remains supported. See [fixed-tag combinations and compatibility](https://github.com/fbincon/claude-code-statusline/blob/v1.3.0/docs/USER_GUIDE.md#editor-installation-combinations-and-compatibility).

In Client, click the region once, then use Tab for pages, arrows for navigation/order, Space for toggles, `/` for search and Ctrl+G to cancel input. `s` saves/continues, `f` saves/finishes and `q` discards/closes. Esc belongs to the host. Advanced Claude preferences Apply separately; unknown save outcomes must be checked before retrying or closing. The external TUI retains its original shortcuts and platform launchers.

Existing Python/platform support, display schemas and JSON protocol v1 remain compatible. Backend and Mod versions are both 1.3.0. Assets are the matching wheel, source distribution and SHA256SUMS; this is a stable Release selected as Latest.

## Validation and acceptance

Local regression passed 444 Python tests with 8 platform skips, 34 official Mod tests on each fixed Linux host 2.1.287/2.1.288, strict official validation, TypeScript, Ruff and shared-contract checks. Documentation checks cover 310 relative links, bilingual pairs, required configuration entries and preserved legacy anchors. Ten isolated upgrade cases from the actual v1.2.0/a2 wheels passed, including missing preferences, saved true/false, historical external disablement and host-disabled plugins.

Installed-wheel Linux PTYs with fixed Claude Code 2.1.288 passed at 120×30 and 80×48, covering both entries, click-to-focus, editing, save/exit, Esc and returning to the original session. Publication requires all 13 Python/build and four fixed Mod CI jobs on the PR, merge commit and tag, plus resource hashes, independent rebuilds/installs and draft/public download verification. Actual run links accompany the published Release.

On 2026-10-04 the maintainer explicitly confirmed v1.3.0a2 human acceptance passed on Linux, Windows and macOS, separately from a1. Exact terminal, architecture and host metadata were not supplied with the confirmation and remain unknown. Client interaction modules are unchanged from a2; this promotion updates version/description, installation policy and documentation. Automated checks are recorded separately and are not human acceptance. No paid model/timer suite was run.

# v3.7.0 — Indicators, groups and session-aware metrics

Configure optional percentage bars, linked groups, automatic GitHub refresh and hourly cost estimates through shared CLI and editor controls.

- Context and quota bars retain direction, raw visibility thresholds and missing/stale semantics. Existing numeric output remains the default.
- Main and subagent groups keep decorations with a selected primary, fit as units and optionally share its Powerline background. Copies receive new identities; deleting a primary preserves surviving components.
- GitHub PR/CI automatic refresh is separately reviewed and saved locally until disabled. Supported active sessions renew leases; identity checks, coalescing, manual ownership, backoff and stop controls keep execution separate from rendering. JSON/command sources remain manual.
- `session-cost-rate` estimates cost per session hour or cumulative API hour from official fields. At least one minute is required; valid zero cost remains visible and the denominator stays explicit with labels disabled.
- Display schema 13, editor protocol 21, source registry/jobs 2 and runtime 3 require matching resources. Runtime v1/v2 observe/read remain supported. Old display files migrate without writes until an explicit save; portable files cannot grant source authorization.

Support remains Node 22/24 on Linux, WSL, Windows and macOS. Automatic refresh requires Claude 2.1.289+ and configured runtime integration; it does not require either metric collector or the native editor. No model calls are needed for these features.

See [appearance](../APPEARANCE.md), [composition](../COMPOSITION.md), [sources and automatic refresh](../EXTENSIONS.md), [cost-rate definitions](../DISPLAY_ITEMS.md#session-cost-rate) and [delivery evidence](../development/m4-m7-delivery.md).

Publication is gated on final PR/main/tag automation, eight installed targets, 32 Node cases, thirteen fixed hosts, identical builds/source rebuild, installed terminal verification, verified release assets and public channel checks. The [version-specific maintainer decision](approvals/v3.7.0.json) accepts only the same six unverified #96 gaps; no new failure is waived. Final publication identities and channel results will be recorded after verification.

# v3.9.2: editor, source and diagnosis correctness

## Fixes

- Protect display drafts in both editors while a save is pending or unknown, including source binding and already-open managers. The external TUI adds Ctrl+K to check saved state without repeating a write.
- Compose percentage bars and legacy, hidden, short or custom labels exactly once in main and subagent output across all six languages.
- Separate shared GitHub refresh execution from its consumers. Closing one editor or interrupting one CLI releases only its interest; explicit cancellation still stops the whole job.
- Apply input time to extension diagnosis, exclude later and untimestamped historical values and supporting fields, and retain evidence for every instance/agent pair.
- Load task UI language before command descriptions and initial titles; retain it after task failures and reread it on retry/reopen. Bound the plain task pane without discarding the full report.

## Compatibility and validation

Editor protocol 25 and source jobs 3 require matching installed frontend/backend resources. Old jobs remain readable without rewriting; running legacy jobs are not joined. Display schema 15, source registry 2, observation 1, runtime 3 and UI preferences 1 remain unchanged. Node 22/24 and all six languages remain supported. Reinstall integration and restart Claude Code after upgrading.

Published as stable/Latest on GitHub and npm, with the same four verified files and annotated source tag on Gitee. Final PR/main/tag gates, OIDC and six public-download jobs passed. The [delivery record](../development/correctness-maintenance.md) records source identities, regression results and machine upgrade/restoration evidence. The [v3.9.2 decision](approvals/v3.9.2.json) accepts only the six existing [issue #96 gaps](https://github.com/fbincon/claude-code-statusline/issues/96), which remain unverified. No new automated failure is waived. No paid model tests are run.

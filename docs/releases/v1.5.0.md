# v1.5.0: Formatting, layouts and host preferences

Stable v1.5.0 promotes the verified Phase 4 preview. On 2026-10-05 the maintainer confirmed human acceptance on Linux and Windows and on macOS through the standalone TUI/CLI. OS, architecture, terminal and exact host versions were not supplied. The earlier macOS in-session Client input limitation remains open; this acceptance does not claim its repair.

- Retain the accepted model/number formats, labels and Unicode/ASCII icons, custom item text, risk thresholds, used/remaining allowances and reset time/time-zone formats. Default status-line appearance is unchanged; missing/expired data remains unavailable and observed zero stays zero.
- Retain explicit rows with priorities and terminal-column widths, subagent filters/limits, four editable presets, portable JSON files, scoped Ctrl+E forms and the Layout page in both editors. Native Claude preferences keep a separate per-row Apply.
- Synchronize Python and Mod at 1.5.0. Both editor entries default on for supported hosts, preserving explicit false and independent compatibility suspension. Upgrading from a1 retains display schema v3, protocol v2 and existing configuration; the historical preview tag/assets and capture provenance remain intact.

## Install or upgrade

Python 3.10–3.14 supports Linux/WSL, Windows and macOS. The external entry requires Claude Code 2.1.258+, the in-session Client 2.1.287+. Install the stable wheel, synchronize integration and restart Claude Code:

```text
pipx install --force "https://github.com/fbincon/claude-code-statusline/releases/download/v1.5.0/claude_code_statusline-1.5.0-py3-none-any.whl"
claude-statusline install
claude-statusline doctor
```

Missing editor preferences follow the stable enabled default; recorded false stays off. To deliberately enable both entries, use `claude-statusline install --experimental-slash-tui --native-editor`. Use `claude-statusline configure` or configuration commands on macOS when Client input is unavailable. [User guide](https://github.com/fbincon/claude-code-statusline/blob/v1.5.0/docs/USER_GUIDE.md#formatting-layout-presets).

Display v1/v2 is normalized in memory without rewriting its file. An actual save backs up original bytes and migrates to v3. Before a package downgrade, close editors, remove native using the newer package, restore the pre-migration display backup according to its metadata, install the older package and rerun install/doctor. [Compatibility and recovery](https://github.com/fbincon/claude-code-statusline/blob/v1.5.0/docs/USER_GUIDE.md#version-compatibility).

## Validation and acceptance

- Local checks cover 507 Python tests (499 pass, eight expected platform skips), 40 official Mod tests, strict plugin validation, TypeScript, shared contracts, Ruff and bilingual documentation. Stable defaults, persistent disablement, installation combinations, compatibility suspension and complete draft saves remain covered.
- The PR, merge commit and tag each require all 18 CI jobs: 13 Python/build and five fixed Mod jobs (Linux 2.1.287/2.1.288/2.1.289, Windows/macOS 2.1.288). The existing Intel/Apple Silicon macOS and Windows/POSIX matrix is retained.
- Installed-wheel Linux PTYs check both persistent entries at 120×30 and 80×48, formats/layouts, CJK files, presets/import/export, save/cancel/readback and separate host preference Apply. Human acceptance, automated checks and agent capture inspection are distinct evidence.
- Build wheel/sdist from the fixed verified merge commit; inspect inventories, independently rebuild/install, compare package bytes and SHA256, verify draft downloads, then publish stable as Latest and check unauthenticated public downloads and isolated URL installations. Detailed evidence remains outside distributions.

The stable promotion changes versions, defaults and documentation without adding Phase 5 runtime indicators or changing timer behavior. No paid model/timer suite is run. [Preview performance measurements and test procedures](https://github.com/fbincon/claude-code-statusline/blob/v1.5.0/docs/development/testing.md#v150a1-candidate-evidence).

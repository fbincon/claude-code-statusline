# Component composition

Build a status line from independent component instances. Repeat a metric with different labels, icons, formats, colors, visibility, priority and width; add literal text and a flexible spacer to align an explicit main row or the subagent template. Existing default display content remains unchanged. The **Left and right** and **Repeated metrics** presets provide editable examples.

Both editors show configured instances, including disabled entries. Native **A/D/X** and external **Ctrl+A/Ctrl+D/Ctrl+X** add, copy and remove instances. The searchable type picker, instance forms, ordering, preview and import review share the same configuration model. The CLI provides scoped `config instance` operations and `config layout --by-instance`; legacy type commands reject ambiguous matches. See the [composition guide](../COMPOSITION.md) and [CLI reference](../reference/cli.md).

```text
pipx install --force fbincon-claude-code-statusline==2.0.0
claude-statusline install --dry-run
claude-statusline install
claude-statusline doctor
```

Restart Claude Code after updating its integration. Stable installation requests both supported editor entries by default and retains explicit disablement. Interface language, output language, collectors and Claude preferences remain independent. Upgrading the Python package alone does not update installed editor resources.

## Compatibility and recovery

Display schema **8** and editor protocol **11** require matching Python and bundled resources. Display v1–v7 files migrate deterministically in memory, preserving enabled order, disabled overrides, layout and language. Reads, previews, import review and dry runs do not rewrite display files. Actual saves and installation back up before migration and retain revision checks and transaction rollback.

Portable envelopes remain v1, UI preferences v1 and runtime observations v2. Before downgrading, remove incompatible native integration with the current package and restore a compatible pre-migration backup before installing the older package. Repeated instances and flexible layouts cannot be converted losslessly by changing the schema number. See [upgrade and recovery](../USER_GUIDE.md#version-compatibility).

Linux/WSL, Windows 10/11, macOS 14+ and Python 3.10–3.14 remain supported. External entry needs Claude Code 2.1.258+ and Client needs 2.1.287+; incompatible entries suspend independently. Repeated metrics share raw observations within a frame and format each instance separately. Timer and observation-store semantics remain unchanged.

## Validation

The composition candidate completed 815 Python tests (807 passed, eight platform skips), 112 native Mod tests and ten runtime Mod tests. Installed-wheel validation covered ten bilingual external PTY cases at five sizes, four bilingual native composition cases at two widths, native/external discovery and import review, six grapheme/style cases and released v1.13.0 migration, compatible-backup downgrade and re-upgrade. Independently rebuilt wheels retained 217 identical internal files. [Capture provenance](../images/composition/README.md) records the tested sources and terminal reconstruction limits.

[Performance measurements](../development/performance-v2.0.0.md) retain 39,000 baseline comparison samples and 10,000 opt-in composition samples. Instance validation and retained disabled placements add work; measured costs and screening flags remain in the report. This release does not claim zero default-path overhead. Stable promotion changes release metadata, documentation and version-dependent installation defaults; the measured rendering and collection code is retained.

The release process requires all 13 Python/build and 13 Mod jobs on the reviewed PR, merge commit and tag, independent package rebuilding, installed smoke and preview-to-stable upgrade checks. The same fixed artifacts pass nine TestPyPI and nine PyPI publishing/installation jobs before synchronization to Gitee. The [preview](https://github.com/fbincon/claude-code-statusline/releases/tag/v2.0.0a1) remains available with its original assets.

Ten fixed-host Mod jobs retain exact-build TypeScript checks. The three Claude Code 2.1.296 jobs cover runtime tests, strict validation and installation; the current host preparation flow does not emit its declarations, so these are not exact-build 2.1.296 type checks. Automated captures and agent inspection do not establish new human Windows/macOS acceptance. The historical [macOS Client focus/input limitation](../USER_GUIDE.md#macos-mouse-reporting-and-client-focus) remains. No paid model calls were needed for composition or stable promotion.

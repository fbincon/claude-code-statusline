# v1.7.0a1 — Task timing preview

This prerelease introduces task timing across submission, queueing, parallel agents, delivered reports and main-agent wrap-up. It is published with **Latest disabled**; [v1.6.1](https://github.com/fbincon/claude-code-statusline/releases/tag/v1.6.1) remains the stable installation target.

## Behavior

- `task-timer` replaces the default prompt clock in the same position. `prompt-timer` remains a compatibility alias in CLI commands, imports, item options and explicit layouts. Conflicting aliases are rejected.
- Optional `task-active-timer` measures execution without proven user waits. It appears only when identity, event coverage, wait boundaries and boot-clock evidence are complete. `doctor` explains missing evidence; unsupported permission/question/MCP wait boundaries hide it.
- A raw Stop is a candidate shown as a lower bound (`? …+`). Verified continuation keeps the original task clock. Native completion or matched compatibility evidence confirms an ending; failures and interruptions freeze. Child work, report delivery and main wrap-up remain part of the task.
- Native `durationMs` stays separate from total task time. A real parallel probe retained about 14.1 seconds of task time although its final native turn reported 3.7 seconds. Parallel execution is counted once.
- Immutable pause/resume state survives refresh processes, and indexed submission evidence avoids repeated history scans. Windows uses a boot GUID with uptime; Linux and macOS retain suspend-aware clocks. Missing execution-clock evidence invalidates precision.

## Installation and migration

```bash
pipx install --force "https://github.com/fbincon/claude-code-statusline/releases/download/v1.7.0a1/claude_code_statusline-1.7.0a1-py3-none-any.whl"
claude-statusline install
claude-statusline config enable task-active-timer
claude-statusline doctor
```

Claude Code 2.1.289+ fresh installs default to timing metadata on and advanced metrics off. Reinstall preserves saved choices. Old runtime preference `live_metrics=false` keeps both off; old true keeps both on. `--native-timing` / `--no-native-timing` controls timing independently. `--live-metrics` retains full collection and `--no-live-metrics` retains the legacy all-off behavior; an explicit timing switch overrides that timing choice. Unsupported/unknown hosts use compatibility evidence without changing preferences.

Display schema v5, configuration protocol v4, runtime preferences v2, runtime protocol v2 and lifecycle v4 ship together. Supported old display/lifecycle files are read in memory; actual configuration saves/install transactions back up and migrate. Runtime protocol v1 cannot claim complete execution coverage. Historical frozen values remain historical evidence.

Before downgrading, use this package to run `install --no-native-timing --no-live-metrics`, remove editor integrations the old package cannot manage, and restore compatible display/runtime preference backups. Then install the old package, reinstall integration and restart Claude Code. See the [user guide](../USER_GUIDE.md#task-timing-preview).

## Validation and boundaries

- Local Python: 586 tests, 578 passed and eight expected platform skips. Ruff, generated contracts, documentation links, official static validation, both TypeScript projects and 51 official Mod tests passed.
- Real Linux x86_64 / Python 3.14.4 / Claude Code 2.1.289: single-agent, parallel agents and wrap-up, blocked Stop continuation, SDK-controlled question waiting and interruption, native timing and explicitly disabled compatibility collection passed. Production total/available execution values freeze after endings; missing execution evidence is hidden. All attempts and retries use the same persistent USD 10 ledger; recorded spend before final distribution revalidation was USD 0.801859 with no unknown cost.
- Identical benchmark/interpreter/machine, 30 samples, histories of 100/10,000/100,000 rows and one/32 retained tasks: at 100,000 rows/32 tasks, terminal submission P50/P95 changed from 9.49/9.59 ms to 0.05/0.06 ms. Unchanged hot refresh reads no transcript data. First indexing still reads the history; local fixtures and scheduler noise limit these measurements. See [testing and full performance details](../development/testing.md#task-timing-preview-validation).
- All applicable PR, merge and tag CI, fixed-merge wheel/sdist inspection, independent rebuild and isolated installations are release gates. CI covers Windows and Intel/Apple Silicon macOS alongside Linux; exact workflows and run links are available on the [PR](https://github.com/fbincon/claude-code-statusline/pull/39) and [Actions](https://github.com/fbincon/claude-code-statusline/actions).
- SDK inputs were automated. This preview does **not** claim new human interactive acceptance, real machine sleep/resume acceptance or real Windows/macOS model-session acceptance. Simulated suspend, wall adjustment and reboot checks are separate from hardware acceptance. The existing macOS Client input limitation remains; raw sessions/configuration/reports stay private.

## v1.7.0a1 — 任务计时预览版

本预览版覆盖真实提交、排队、并行 Agent、报告交付和主 Agent 收尾。发布为 **prerelease，Latest=false**；稳定安装入口继续指向 [v1.6.1](https://github.com/fbincon/claude-code-statusline/releases/tag/v1.6.1)。

### 行为

- 默认计时项在原位置改为 `task-timer`。CLI、导入、逐项选项及显式布局保留 `prompt-timer` 别名；归一化后的冲突明确报错。
- 可选 `task-active-timer` 扣除可信用户等待，仅在身份、事件覆盖、等待边界和启动时钟证据完整时显示。缺失证据由 `doctor` 解释；不能核验权限、问题或 MCP 等待边界时隐藏。
- 原始 Stop 为停止候选，显示下界 `? …+`；可信续跑保留原任务起点，原生结束或匹配兼容证据确认终态，失败及中断冻结。子 Agent 工作、报告和主 Agent 收尾仍属于原任务。
- 原生 `durationMs` 独立保存。真实并行场景的最后单轮为约 3.7 秒，任务总耗时仍为约 14.1 秒；并行执行不重复相加。
- 不可变暂停／恢复状态跨刷新进程持久化，提交索引避免重复全历史扫描。Windows 使用启动 GUID 与 uptime；Linux/macOS 保留包含睡眠的时钟。缺失执行时钟证据使精确值不可用。

### 安装与兼容

```bash
pipx install --force "https://github.com/fbincon/claude-code-statusline/releases/download/v1.7.0a1/claude_code_statusline-1.7.0a1-py3-none-any.whl"
claude-statusline install
claude-statusline config enable task-active-timer
claude-statusline doctor
```

Claude Code 2.1.289+ 新安装默认开启计时元数据，高级指标默认关闭；重装保留选择。旧偏好显式 false 保留为两者关闭，true 保留为两者开启。新增 `--native-timing`／`--no-native-timing` 独立控制计时；原 `--live-metrics` 开启完整采集，`--no-live-metrics` 保留全部关闭行为，同一命令明确给出的计时选项覆盖计时选择。不兼容或未知宿主走兼容证据路径，不改变偏好。

本版同时使用显示 schema v5、配置协议 v4、运行偏好 v2、运行协议 v2 和生命周期 v4；支持的旧配置／状态只在内存读取，实际保存或安装事务才备份迁移。运行协议 v1 不声明完整执行覆盖，历史冻结值保留为历史证据。

降级前用本版执行 `install --no-native-timing --no-live-metrics`，移除旧包不能管理的编辑器，恢复兼容显示／运行偏好备份，然后安装旧包、重装接入并重启 Claude Code。详见[使用指南](../USER_GUIDE.zh-CN.md#任务计时预览)。

- 本地 Python 共 586 项测试，578 项通过、8 项预期平台跳过；Ruff、生成契约、文档链接、官方静态验证、两个 TypeScript 项目和 51 项官方 Mod 测试通过。

- SDK 输入为自动控制。本版不声明新的真人交互、真实机器睡眠／恢复或真实 Windows/macOS 模型会话验收。模拟校时／睡眠／重启与硬件验收分别记录；现有 macOS Client 输入限制保留。原始会话、配置和报告均保持私有。

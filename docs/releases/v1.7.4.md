# v1.7.4 — PyPI publishing and package identity

The distribution name is now `fbincon-claude-code-statusline`. The command remains `claude-statusline`, the Python import remains `claude_statusline`, and saved configuration, ownership markers, portable exports and both Mod integrations stay compatible.

## Install or migrate

```text
pipx install fbincon-claude-code-statusline
claude-statusline install --dry-run
claude-statusline install
claude-statusline doctor
```

Existing users of this repository's older wheel must first follow the [package-name migration](https://github.com/fbincon/claude-code-statusline/blob/v1.7.4/docs/USER_GUIDE.md#migrate-the-previous-distribution-name). The old name on PyPI belongs to another project. Confirm the old installation's source before removing its pipx environment. Display settings, preferences and runtime state remain available; reinstallation refreshes command paths and backend bindings. Restart Claude Code afterward.

## Publishing and documentation

- GitHub Actions uses trusted publishing with separate TestPyPI and PyPI environments. Only the upload job receives an identity token. Actions are pinned to commit hashes and generate publishing attestations.
- Publication verifies the fixed tag/main commit, complete Python/Mod CI, asset names, SHA256, metadata and resource inventories. TestPyPI acceptance precedes formal upload, which starts when the GitHub Release becomes public. Verified existing files allow partial-upload retries without replacing artifacts.
- Six index jobs download and install the same wheel on Linux, Windows and macOS with Python 3.10/3.14. Source distributions and wheels retain the same hashes across PyPI, GitHub and the task-driven Gitee synchronization.
- Both READMEs use generic package-name commands without a project-version/update section. Their image and documentation links work as PyPI long-description links. The bilingual user, development and release guides cover migration, strict metadata checks and publisher setup; the expanded tree includes build/publication tools.

Python and both Mods are 1.7.4. Display schema v5, configuration protocol v4 and runtime protocol v2 retain their compatibility. Existing platform/terminal limitations and historical human acceptance keep their original scope; this publication change makes no paid model calls.

## Local validation

- Python: 614 tests, with 606 passes and eight expected platform skips; 15 publication-gate tests cover identity, checksums, CI, safe redirects, missing/partial uploads and exact index downloads.
- Claude Code 2.1.292 on Linux: 55 native and 10 runtime official tests, strict validators, both TypeScript checks and generated contracts passed. Installed-wheel core/native/runtime smoke passed using isolated configuration without model calls.
- Documentation: 805 repository links and bilingual pairs, rendered Markdown links/images, Ruff, workflow syntax and strict package metadata passed. Independent sdist rebuilding produced identical content for all 156 wheel files.
- Actual 1.7.3-to-1.7.4 pipx migration preserved display/preference/runtime bytes, saved disablement and native binding, refreshed command paths, passed doctor and retained data after repeat install/uninstall. Publication additionally requires complete PR/main/tag CI and both index workflows.

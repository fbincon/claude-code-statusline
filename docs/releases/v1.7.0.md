# v1.7.0 — Task timing

The accepted task timing preview is now the stable Latest release. On 2026-10-07 the maintainer confirmed v1.7.0a1 validation on Linux, macOS and Windows. Python and both Mods are 1.7.0; the accepted timing implementation and schema contracts continue in this release.

## Task timing and compatibility

- Default `task-timer` measures the complete user task, including submission, queueing, child agents, delivered reports and main-agent wrap-up. `prompt-timer` remains a compatibility alias in CLI commands, imported configurations, item options and explicit layouts.
- Optional `task-active-timer` counts execution once across parallel work and deducts proven user waits. It appears only with complete identity, event, waiting and boot-clock evidence; `doctor` explains unavailable results.
- Raw Stop remains a candidate. Verified continuation retains the original task start, and trusted native or compatibility evidence confirms completion. Failed, interrupted and confirmed completed tasks freeze; native turn duration stays separate.
- Supported old files remain readable. Display schema v5, configuration protocol v4, runtime preferences v2, runtime protocol v2 and lifecycle v4 match the accepted preview. Actual saves and install transactions retain migration backups; historical frozen values remain historical evidence.

## Install or upgrade

```bash
pipx install --force "https://github.com/fbincon/claude-code-statusline/releases/download/v1.7.0/claude_code_statusline-1.7.0-py3-none-any.whl"
claude-statusline install --dry-run
claude-statusline install
claude-statusline doctor
```

Restart Claude Code after integration. On Windows use `claude-statusline.exe`.

Compatible stable installations request both the external editor and in-session Client. Saved false values and explicit plugin disablement remain respected. Claude Code 2.1.289+ fresh installs default to native timing metadata on and advanced metrics off; editor enablement and collection preferences are independent.

Use `--native-timing` / `--no-native-timing` to select timing. `--live-metrics` enables advanced collection; `--no-live-metrics` retains the legacy all-off behavior. To retain timing while disabling advanced metrics, use `install --no-live-metrics --native-timing`. Unsupported or unknown hosts use compatibility timing and suspend unavailable integrations while retaining choices.

The a1 preview tag, assets and prerelease status are preserved. See the [user guide](../USER_GUIDE.md#task-timing) and [release procedure](../RELEASING.md#v170-stable-promotion) for migration and downgrade guidance.

- Maintainer confirmation covers Linux, macOS and Windows. Exact OS, architecture, terminal and host versions were not supplied. Automated CI, controlled SDK scenarios and hardware sleep/resume are recorded separately; no specific hardware sleep/resume result was supplied with this confirmation.
- Local verification uses the existing 590-test Python suite (582 passes, eight expected platform skips), Ruff, generated contracts, documentation checks, both TypeScript projects and 51 official Mod tests.
- Stable publication requires complete PR, fixed-merge and annotated-tag CI, installed core/native/runtime smoke, a1-to-stable upgrades and both editor PTYs, wheel/sdist inventories, independent rebuild/install, draft/public bytes and SHA256, and isolated public-wheel/fixed-tag URL installs.
- Six captured real task scenarios are revalidated on the stable wheel without new paid model calls. The original USD 10 ledger is preserved at USD 0.801859, with no unknown or reserved cost.
- Execution timing still requires trustworthy coverage. Missing approval/question/MCP wait boundaries hide execution time; the earlier macOS Client focus troubleshooting remains available in the user guide.

### 计时与兼容

- 默认 `task-timer` 包含用户提交、排队、子 Agent 工作、报告交付及主 Agent 收尾。CLI、导入、逐项设置和显式布局继续支持 `prompt-timer` 别名。


# Component composition preview

Create multiple instances of the same metric, each with its own label, icon, format, colors, visibility, priority and width. Add literal text and one flexible spacer per explicit main row or subagent template. The existing default display remains unchanged; the new **Left and right** and **Repeated metrics** presets provide editable starting points.

Both editors list configured instances, including disabled ones. Native A (external Ctrl+A) opens a searchable type picker, native D (external Ctrl+D) copies and native X (external Ctrl+X) removes. Existing enable, format and ordering controls operate on the selected instance. The CLI adds scoped `config instance` operations, and import review follows instance identity. Legacy type commands refuse ambiguous matches or compositions they cannot preserve. See the [composition guide](../COMPOSITION.md).

```text
pipx install --force fbincon-claude-code-statusline==2.0.0a1
claude-statusline install --native-editor --experimental-slash-tui
claude-statusline doctor
```

Restart Claude Code after updating its integration. The preview retains the established explicit editor opt-in policy. Interface language, output language, collectors and Claude preferences remain independent.

## Compatibility and recovery

Display schema **8** and editor protocol **11** require matching Python and bundled resources. Supported display v1–v7 files map deterministically in memory, preserving enabled order, disabled overrides, layouts and language. Reads, previews, import review and dry runs do not rewrite display files. Actual saves or installation back up before migration and retain revision checks and transaction rollback.

Portable envelopes remain v1, UI preferences v1 and runtime observations v2. Before downgrading, use the current package to remove incompatible native integration and restore a compatible pre-migration backup before installing the older package. Repeated instances and flexible layouts cannot be converted losslessly by changing the schema number. See [upgrade and recovery](../USER_GUIDE.md#version-compatibility).

Linux/WSL, Windows 10/11, macOS 14+ and Python 3.10–3.14 remain supported. Grapheme fitting, color fallback and Powerline boundaries use the existing production/sample pipeline. Copies share raw observations without additional transcript scans or Git collection; timing and observation stores keep their existing semantics.

## Validation boundaries

Local validation completed 815 Python tests (807 passed, eight platform skips), 112 official native Mod tests and ten runtime Mod tests. Installed wheels passed ten bilingual external PTY cases at five sizes, four bilingual native cases at two widths, six grapheme/style PTY cases, CLI/install smoke and a released-wheel upgrade/downgrade/re-upgrade check. An independent wheel rebuild retained 217 identical internal files. [Captured interfaces](../images/composition/README.md) distinguish terminal reconstruction from human acceptance.

[Performance measurements](../development/performance-v2.0.0.md) retain 39,000 comparison samples and 10,000 opt-in samples, including measured costs and screening flags. Instance option validation and retained disabled placements add work; the release does not claim zero default-path overhead.

Release gates include the Python suite, official Mod tests and exact-build TypeScript checks, generated-resource parity, wheel/sdist inventories, independent rebuilds, installed bilingual Linux PTYs, migration/recovery and fixed-source cold/warm performance measurements. Final PR, merge and tag must pass 13 Python/build and 13 Mod jobs, followed by nine TestPyPI and nine PyPI publication/installation jobs using the same artifacts.

The earlier ten fixed-host Mod jobs retain exact-build type checks. Claude Code 2.1.296 adds three-platform runtime, strict validation and installation coverage; the current host preparation flow does not emit its declarations, so these are not exact-build 2.1.296 type checks. Automated terminal captures and agent inspection do not establish new human Windows/macOS acceptance. The historical [macOS Client focus/input limitation](../USER_GUIDE.md#macos-mouse-reporting-and-client-focus) remains. No new paid model calls are required for composition.

# v1.1.1 · Timer correctness and project structure

v1.1.1 fixes end-to-end task timing and reorganizes the Python implementation while retaining the existing CLI, display configuration and platform support.

## Changes

- Preserve an eight-second multi-agent task when a delayed native duration reports one second. Subagent history continues to block inferred completion after the main agent resumes.
- Keep host-generated background-agent notification prompt IDs in the original human task. Wait for pending reports and main-agent wrap-up, including reports delivered after an apparent Stop.
- Freeze accepted failure/interruption evidence, make duplicate terminal hooks idempotent, and retain one eligible calibration for an ordinary successful single turn. Resolve submission evidence before freezing; later transcript refreshes do not change terminal duration.
- Separate task elapsed, native turn duration, session runtime and cumulative API wait. The existing `cost` item describes the session runtime it actually renders.
- Split configuration, rendering, runtime, integration, UI and platform implementation; retain legacy Python module entry points, shared callable identities and error exit codes. Group tests by subsystem and fix relocated source/Terminal child-process paths.
- Centralize documentation and package validation, installed-package smoke and opt-in real timer acceptance under `tools/`; add English/Chinese architecture, testing and timer-contract documents.

## Compatibility and installation

Linux/WSL and Windows 10/11 retain Python 3.10+ support; native Windows supports CPython 3.10–3.14 x86/x64 with `windows-curses>=2.4.2`. macOS 14+ retains CPython 3.10–3.14 Intel/Apple Silicon support with native curses. Windows ARM64 native Python remains outside the declared support range; x64 emulation is available.

Claude Code minimums remain unchanged: subagent rows require 2.1.205+, task effort requires 2.1.214+, and fast local configuration/experimental launchers require 2.1.258+. The experimental slash TUI remains disabled by default. This release does not add a native Mods editor.

Display schema v2, feature schema v1, runtime mirror schema 1 and lifecycle schema 3 remain compatible. Optional duration/agent/continuation metadata does not require user configuration migration. Timing scan version 5 rechecks old transcript metadata without resetting cumulative usage.

```text
pipx install "https://github.com/fbincon/claude-code-statusline/releases/download/v1.1.1/claude_code_statusline-1.1.1-py3-none-any.whl"
pipx ensurepath
```

For an existing installation, add `--force` to `pipx install`. Reopen the terminal and run `claude-statusline --version`, `install --dry-run`, `install` and `doctor`; on Windows use `claude-statusline.exe`. Fixed-tag source is available with `pipx install "git+https://github.com/fbincon/claude-code-statusline.git@v1.1.1"`.

Attachments are the pure-Python wheel, source distribution and `SHA256SUMS`. Verify downloaded files with `sha256sum -c SHA256SUMS` on Linux/WSL, `shasum -a 256 -c SHA256SUMS` on macOS, or `Get-FileHash -Algorithm SHA256` on Windows.

## Validation and boundaries

Local validation passed 383 unittest cases (8 platform-specific skips), 60 timer/lifecycle regressions, Ruff F/E9, whitespace checks and relative documentation-link/anchor checks. New ordering regressions failed before their corresponding repairs.

Real Linux acceptance used Python 3.14.4 and Claude Code 2.1.288. A single-agent case and two genuine parallel-agent cases completed with the production reducer and renderer. One parallel sequence recorded main Stop while two agents were active, two agent stops, report-notification prompt changes and final wrap-up. The other completed both agents before the first main Stop, then continued the original task to consume their reports. Frozen displays were `✓ 0m 02s`, `✓ 2m 02s` and `✓ 1m 53s`, stable across later transcript refreshes.

These were real print-mode hooks/transcripts, not an interactive visual acceptance claim. This host's print-mode transcripts contained no native `turn_duration` records; native-duration precedence and late-arrival permutations were validated through regression tests. No new Windows/macOS visual support is claimed.

Publication requires the complete 13-job Linux/Windows/macOS/Python CI on the final PR, merge and tag commits, clean fixed-commit builds, package-content inspection, draft/public asset digest checks and isolated installations. Actual final commit, CI and download verification results accompany the published Release.

v1.1.1 修复任务端到端计时，重整 Python 实现，保留现有 CLI、显示配置和平台支持。

## 主要变化

- 迟到的原生 duration 为 1 秒时，完整 8 秒的多 Agent 任务保持不变。主 Agent 恢复后，子 Agent 历史仍阻止弱证据推断完成。
- 将后台 Agent 结果通知的新宿主 prompt ID 关联回最初的人类任务，等待报告交付及主 Agent 收尾，包括表面 Stop 后才交付的报告。
- 冻结失败/中断证据，让重复终态 hook 保持幂等；普通成功单轮保留一次有效校准。冻结前核对提交证据，后续 transcript 刷新不改变终态耗时。
- 区分任务耗时、原生单轮、会话运行时间与 API 累计等待时间，修正 `cost` 的会话运行时间描述。
- 按配置、渲染、运行、集成、UI 和平台拆分实现，保留旧 Python 模块入口、函数共享身份和错误退出码；按子系统归类测试，修复移动后的源码/Terminal 子进程路径。
- 在 `tools/` 统一文档/包验证、已安装包 smoke 与显式真实计时验收，新增中英文架构、测试及计时约定。

## 兼容与安装

Linux/WSL、Windows 10/11 保留 Python 3.10+ 支持；Windows 原生范围为 CPython 3.10–3.14 x86/x64，自动安装 `windows-curses>=2.4.2`。macOS 14+ 保留 CPython 3.10–3.14 Intel/Apple Silicon 支持，需原生 curses。Windows ARM64 原生 Python 仍不在声明范围内，可使用 x64 仿真。

Claude Code 最低版本不变：子 Agent 行 2.1.205+、任务 effort 2.1.214+、本地快捷配置/实验启动器 2.1.258+。实验 slash TUI 默认关闭，本次未新增原生 Mods 编辑器。

显示 schema v2、feature schema v1、运行镜像 schema 1 与生命周期 schema 3 保持兼容。可选时长/Agent/续接元数据无需迁移用户配置。计时扫描版本 5 重新核对旧 transcript 元数据，不重置累计用量。


## 验证与边界

本地通过 383 项 unittest（8 项平台相关跳过）、60 项计时/生命周期回归、Ruff F/E9、空白与相对文档链接/锚点检查。新增事件顺序回归在对应修复前确实失败。

真实 Linux 验收使用 Python 3.14.4、Claude Code 2.1.288。单 Agent 与两次真实并行 Agent 场景由生产 reducer 和 renderer 验证完成。一轮记录主 Stop 时仍有两个 Agent、两次 Agent Stop、结果通知 prompt ID 变化及最终收尾；另一轮在首个主 Stop 前已结束两个 Agent，随后仍继续原任务以接收报告。冻结显示为 `✓ 0m 02s`、`✓ 2m 02s`、`✓ 1m 53s`，后续 transcript 刷新保持稳定。

这些是实际 print 模式 hooks/transcript，不代表交互视觉验收。该宿主的 print transcript 不产生原生 `turn_duration`；原生时长优先级和迟到排列通过回归验证，不新增 Windows/macOS 视觉支持声明。

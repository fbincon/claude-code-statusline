# v3.1.4 — Runtime startup and usage-index publication

[English](#english) | [简体中文](#简体中文)

<a id="english"></a>

Keep bare runtime observations and read-only runtime preferences outside display,
editor and interface-language initialization. Protocol validation, input limits,
localized CLI failures and configuration-directory resolution remain compatible.
The startup fast path applies only to `runtime` without CLI flags. The installed
Mod passes `--config-dir` and retains the existing command route; no Mod end-to-end
startup improvement is claimed.

Coalesce repeated immutable usage-index page updates within the existing cache
lock. A bounded 32 MiB serialized overlay publishes durable pages before the
manifest and atomic state commit; overflow uses the same durable writes.
Exact message replay, integer counters, file cursors and recovery remain intact.

Add verified installed-package benchmarks with complete cache snapshots, separate
counter diagnostics and fresh-process peak RSS. Performance is workload-dependent;
this release makes no claim of universal speed or memory improvement, or of a D06
pass. See [PERF-01 methodology and evidence](../development/performance/perf-01.md).

On the measured Linux host, medium/large cold collection P50 fell 33.6%/47.5%;
large cold peak RSS rose 26.1 MiB (5.0%). Small latency costs and all 36 workloads
are retained in the [completed measurements and delivery report](https://github.com/fbincon/claude-code-statusline/blob/main/docs/development/performance/perf-01.md#delivery-v314).

Upgrade with `npm install --global --ignore-scripts @fbincon/claude-code-statusline@3.1.4`,
run `claude-statusline install`, then restart Claude Code. Node 22/24, six languages,
display schema 8 and configuration/runtime protocols 12/2 remain supported.

The [v3.1.4-only decision](approvals/v3.1.4.json) accepts the same six existing
physical/desktop/exact-declaration gaps, which remain unverified. New functional
or automated failures are not waived. Historical D06 FAIL and Python rollback
artifacts remain unchanged; the existing npm beta selector is preserved.

不带 CLI 参数的 `runtime` 观察及只读运行偏好不再加载显示配置、编辑器和界面语言初始化资源。
保留协议校验、输入上限、CLI 错误本地化和配置目录解析行为。启动快速路径仅适用于
不带参数的 `runtime`；已安装 Mod 会传入 `--config-dir` 并使用既有命令路由，
本次不宣称 Mod 端到端启动提速。

在既有缓存锁内合并精确用量索引页的重复更新。序列化暂存上限为 32 MiB，依次持久化
索引页、manifest 和原子状态提交；超出暂存上限时仍执行相同的持久化写入。
保留消息重放精确去重、整数计数、文件游标和恢复能力。

增加已验证安装包基准，完整恢复缓存快照、单独诊断采集次数并测量新进程峰值 RSS。
效果依赖负载，不承诺所有场景提速或降内存，也不宣称 D06 通过。
参见 [PERF-01 方法与证据](../development/performance/perf-01.zh-CN.md)。

在实测 Linux 主机上，中／大型冷缓存采集 P50 下降 33.6%／47.5%，大型冷缓存峰值 RSS
增加 26.1 MiB（5.0%）。保留的小幅延迟代价及全部 36 个负载见
[完整测量与交付报告](https://github.com/fbincon/claude-code-statusline/blob/main/docs/development/performance/perf-01.zh-CN.md#delivery-v314)。

升级执行 `npm install --global --ignore-scripts @fbincon/claude-code-statusline@3.1.4`，
运行 `claude-statusline install` 后重启 Claude Code。继续支持 Node 22／24、六种语言、
显示 schema 8 和配置／运行协议 12／2。

[v3.1.4 专属决定](approvals/v3.1.4.json)仅接受原有六项实机／桌面／精确声明缺口，
继续标为未验证，不豁免新增功能或自动化失败。历史 D06 FAIL、Python 回退产物及
现有 npm beta 选择器保持不变。

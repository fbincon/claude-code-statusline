# v3.9.0: selective import, gradients and explicit-row alignment

## Features

- Import selected global presentation settings, a complete main section, a complete subagent section, or a combination. Both editors begin selection mode with nothing selected, show the candidate differences and keep accepting a draft separate from saving it. CLI dry runs and named/project targets preserve unselected settings and local source authority.
- Add static component foreground and Powerline background gradients. Ocean, sunset and aurora presets expand to 2–5 RGB stops. Final visible graphemes and block padding determine the color range; thresholds keep their foreground priority, and shared groups use the primary background.
- Align corresponding components or whole groups in explicit main rows using stable IDs. Hidden items retain needed slots; wholly hidden columns and rows collapse. Width pressure removes alignment spaces before existing fitting. Invalid structural changes identify affected relationships before saving.
- Repair version rollback across editor protocols by handing off verified target Mod resources and refreshing owned plugin caches while preserving disablement and unrelated settings.

## Compatibility

Display schema is 15 and editor protocol is 24. Portable/profile envelopes remain 1; source and runtime formats retain their existing versions. Supported old configurations normalize in memory; saving or installation backs them up before migration. Defaults and presets do not enable gradients or alignment. SHOWCASE-01 remains planned.

Before downgrading, preserve your current configuration and explicitly restore a compatible pre-upgrade backup with `recover --restore-config TRANSACTION_ID`. Older packages must refuse the new display schema. Changing its schema number is not a conversion.

Node 22/24 and the existing platforms remain supported. See [CLI reference](../reference/cli.md), [selective import](../PROFILES.md#selective-import), [gradients](../APPEARANCE.md#static-component-gradients) and [alignment](../COMPOSITION.md#align-corresponding-columns-across-main-rows).

## Verification and publication

Final release PR, main and tag gates, independent/source builds, installed terminal evidence and public GitHub/npm/Gitee verification are required before publication. The [delivery record](../development/m10-m12-delivery.md) tracks the actual source and artifact receipts. The [version-scoped maintainer approval](approvals/v3.9.0.json) accepts only the six pre-existing [#96](https://github.com/fbincon/claude-code-statusline/issues/96) gaps; they remain unverified and do not waive any automated failure.

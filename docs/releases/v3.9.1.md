# v3.9.1: native editor capacity and recovery

## Fixes

- Keep complete editing state in the host and send only visible presentation to the Client. Quick setup, import review, display schemes, data sources, explanations and gradients no longer expand each frame with whole draft/library copies ([#154](https://github.com/fbincon/claude-code-statusline/issues/154)).
- Use constant layout nodes for blank regions and borders. Tall panes remain usable; presentation budgets reduce page height and then width when necessary, preserving colors, draft content and paging ([#155](https://github.com/fbincon/claude-code-statusline/issues/155)).
- Preserve successful save results when a later display fails. Retry redraws the retained draft; unknown saves require the existing read-only check before another write.

## Compatibility and validation

Display schema 15 and editor protocol 24 remain unchanged. Node 22/24, six languages and the existing host minimum remain supported. The required matrix adds Claude 2.1.310 on Linux, Windows and macOS, for sixteen host combinations alongside eight installations and 32 Node runtime cases.

All final [PR checks](https://github.com/fbincon/claude-code-statusline/actions/runs/40336709149), [main checks](https://github.com/fbincon/claude-code-statusline/actions/runs/40346292097) and [annotated-tag checks](https://github.com/fbincon/claude-code-statusline/actions/runs/40357902282) passed. Final-package validation passed 197 actual-host capacity cases, 23 installed checks, 17 native/external PTY journeys and 792 six-language light/dark terminal captures plus four terminal controls. Independent builds, the delivered-source rebuild and CI delivery files are byte-identical. The [delivery record](../development/native-capacity.md) records actual results. The [v3.9.1 decision](approvals/v3.9.1.json) accepts only the six existing [#96 gaps](https://github.com/fbincon/claude-code-statusline/issues/96); it does not waive new failures or claim human desktop acceptance.

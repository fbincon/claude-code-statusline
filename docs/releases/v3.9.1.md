# v3.9.1: native editor capacity and recovery

## Fixes

- Keep complete editing state in the host and send only visible presentation to the Client. Quick setup, import review, display schemes, data sources, explanations and gradients no longer expand each frame with whole draft/library copies (#154).
- Use constant layout nodes for blank regions and borders. Tall panes remain usable; presentation budgets reduce page height and then width when necessary, preserving colors, draft content and paging (#155).
- Preserve successful save results when a later display fails. Retry redraws the retained draft; unknown saves require the existing read-only check before another write.

## Compatibility and validation

Display schema 15 and editor protocol 24 remain unchanged. Node 22/24, six languages and the existing host minimum remain supported. The required matrix adds Claude 2.1.310 on Linux, Windows and macOS, for sixteen host combinations alongside eight installations and 32 Node runtime cases.

Production capacity cases, actual-host failure recovery, installed native/external terminal checks and source/artifact identity verification are required before release. The [delivery record](../development/native-capacity.md) records actual results. The [v3.9.1 decision](approvals/v3.9.1.json) accepts only the six existing [#96 gaps](https://github.com/fbincon/claude-code-statusline/issues/96); it does not waive new failures or claim human desktop acceptance.

## 简体中文

修复内部编辑器的两类容量空白：完整编辑状态留在宿主，只传输可见展示，避免快速配置、导入、方案、数据源、说明和渐变重复扩大发送内容（#154）；空白区域与边框改用固定数量布局节点，高面板不再逐行膨胀（#155）。容量不足时先缩小单页高度，再缩小展示宽度，保留颜色、完整草稿和分页。

后续显示失败不会覆盖已成功的保存结果。重试只重绘已接收草稿；保存结果未知时，继续先读取核对，避免重复写入。

显示 schema 15、编辑器协议 24、Node 22／24、六语言及现有最低宿主版本保持兼容。必需矩阵增加三平台 Claude 2.1.310，形成十六个宿主组合，另保留八安装目标和 32 项 Node 用例。发布前须通过生产容量、宿主恢复、安装包终端和来源／产物校验，实际结果见[交付记录](../development/native-capacity.zh-CN.md)。仅接受 #96 六项既有未验证缺口，不豁免新增失败，也不将自动化当作人工桌面验收。

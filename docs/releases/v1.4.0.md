# v1.4.0 — Independent display metrics

This stable release completes the first display-item batches: 24 new opt-in
main items and four subagent items, for a catalog of **48 main / 14 subagent**
items. Existing defaults and compound selections remain available; independent
items can coexist with their compounds in the configured order.

- Select model/effort, live input-context tokens, allowance reset countdowns,
  session cost/runtime, cumulative API duration and edit counts independently.
- Show main-conversation cache warmth/TTL and official request/miss counts,
  output style, session name/full/short ID, or Git branch/change/upstream fields.
- Add optional gateway spend amount/period and cache-inclusive cumulative
  input/output tokens from the existing main/nested-agent accounting.
- Share Git/transcript collection within each refresh; format raw integer
  totals before abbreviation. Expired allowances disappear, expired warm caches
  become cold and lose TTL. Missing observations remain distinct from zero.
- Track input/output observations independently, preserve known totals across
  partial cost snapshots and recover older cached sessions without recounting IDs.
- The shared catalog powers CLI, both editors, the wizard and deterministic
  previews. Display schema v2, runtime persistence and JSON protocol v1 remain
  compatible. Backend and Mod versions are both 1.4.0.

See the [fixed-tag display reference](https://github.com/fbincon/claude-code-statusline/blob/v1.4.0/docs/DISPLAY_ITEMS.md)
for sources, examples, metric scopes and downgrade recovery. Current input-context
occupancy differs from cumulative session consumption; agent context counts
are per task, and official cache request/miss statistics exclude subagents.

## Install or upgrade

```text
pipx install --force "https://github.com/fbincon/claude-code-statusline/releases/download/v1.4.0/claude_code_statusline-1.4.0-py3-none-any.whl"
claude-statusline install
claude-statusline doctor
```

Windows uses `claude-statusline.exe`. Restart Claude Code afterward. Existing
independent editor preferences remain in effect; both entries default on when
no disablement was recorded. Configure through `/statusline-configure-native`,
`/statusline-configure`, standalone `configure`, the wizard or CLI.

Example opt-in main selection:

```text
claude-statusline config set-items model effort current-dir git-branch context-tokens five-hour-reset session-cost api-duration cache-state prompt-timer
```

Cache fields require Claude Code 2.1.251+. Gateway amount/period require 2.1.284+
on both host and gateway and may still be absent. Gateway dollars are estimates
updated separately from allowance percentages. Agent effort requires 2.1.214+
and reports explicitly configured effort, not an inferred inherited value.

Before a package downgrade, remove new IDs in both scopes using the newer CLI
or restore a compatible display backup. Follow native-integration removal steps
separately. Source distributions and wheels retain the same platform support.

## Validation and limitations

Local validation ran 478 Python tests: 470 passed and eight expected platform skips,
35 official Mod tests and strict validation on Linux with Claude Code 2.1.289,
TypeScript, generated contracts, Ruff, bilingual documentation and whitespace
checks. Real isolated official plugin installation saved and previewed the
complete scoped catalog, checked independent editor preferences and uninstalled.

Initial installed-wheel candidate checks on clean commit `9c9d553` passed core smoke and full-catalog official installation. Four persistent Linux PTY cases passed: defaults and all 24 new main items enabled alongside model/directory/Git, each at 120×30 and 80×48. They exercised both editors, click focus, ordering, search, save/cancel, Esc and the 62-item catalog; Agent inspection of captured cells is recorded separately from human acceptance. Wheel/sdist inspection verified 106/273 entries and excluded local reports/roadmaps. Independent wheel rebuild payloads match.

Publication is gated on all 13 Python/build and four fixed-host Mod CI jobs for
the release PR, merge commit and tag, plus distribution inspection, independent
rebuild/isolated installation, installed-wheel Linux PTYs, asset checksums and
public downloads. Actual run links and installed-wheel evidence accompany the
published Release. Ordinary checks send no model prompts; timer behavior is
unchanged and the paid timer suite is not invoked.

The inherited Client interaction retains the documented macOS input limitation
reported on Claude Code 2.1.289. Historical v1.3.0a2 human acceptance on three
platforms remains historical evidence; this release does not claim a new
macOS fix or new three-platform human acceptance.

# v3.4.0 — Display schemes, project bindings and task details

Save named display schemes in either editor, bind project roots to shared schemes, and inspect task evidence on demand.

- Manage schemes with previews, explicit overwrite, import/export and revision-protected saves. The user default remains an independent display snapshot.
- Select the most specific registered project/worktree root, with explained fallback to user defaults. Scheme changes do not enable collectors.
- Open `/statusline-task` or use `claude-statusline task show --session-id ID` for read-only task, attributable-agent, checklist and timing details.
- Use the existing six interface languages, component identities, Unicode editing and separate host-preference controls.

Editor protocol is 15. Display schema 8, runtime protocol 2, lifecycle 4, portable 1 and UI preferences 1 remain unchanged. The new user collection and single-scheme export each use their own version 1. Existing defaults are preserved until an explicit save or activation.

Install or upgrade the npm package, then rerun `claude-statusline install` and `claude-statusline doctor` to refresh owned integrations. Existing editor/collector opt-outs remain effective. Node 22/24 and the existing platform support boundaries are retained.

The [maintainer decision](approvals/v3.4.0.json) accepts only the six historical unverified observations tracked in [#96](https://github.com/fbincon/claude-code-statusline/issues/96). It does not establish physical/desktop acceptance or waive new failures. Task evidence remains bounded, potentially partial and non-atomic across source files.

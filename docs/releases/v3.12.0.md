# v3.12.0 — Source operations, scheduled commands and package execution

**English** | [简体中文](v3.12.0.zh-CN.md)

Source management now provides shared readable state, bounded execution summaries, saved GitHub check pages and reviewed binding maintenance. Automatic commands require separate approval, default to 300 seconds and run only while applicable confirmed contexts retain active leases. Equal inputs share work; distinct contexts rotate fairly with one command per source.

Both editors execute verified upgrades, rollback, unfinished-package recovery and independent configuration restoration. Drafts require explicit handling. Durable controls survive package replacement; the old editor becomes read-only and closing detaches. Reviewed history cleanup protects active work, rollback material and referenced snapshots.

Unverifiable executor identity stays unknown and protected; package recovery waits for confirmed exit or a different identity.

Fix [#173](https://github.com/fbincon/claude-code-statusline/issues/173): ordinary npm manifest permissions no longer cause false package-page compatibility warnings; recovery files retain private permission requirements. [#157](https://github.com/fbincon/claude-code-statusline/issues/157) is closed with actual v3.11.0 tag/OIDC/provenance evidence, retaining the unverified account-capacity limitation.

Editor protocol advances to 28, source registry to 3 for command automatic permission and jobs to 4 for execution summaries. Display schema stays 16; external command observation stays v1. Install matching Mods and reopen the external editor or restart Claude after successful integration. Rollback refuses older packages that cannot read current configuration.

# v3.3.0 — Supplied-input diagnosis and host-field coverage

[English](#english) | [简体中文](#简体中文)

<a id="english"></a>

Use `claude-statusline diagnose --input FILE|-` to inspect explicitly supplied statusline JSON against saved display configuration and attributable existing observations. The CLI provides localized text and `--json` reports; the read-only backend also accepts an unsaved draft. `--scope`, `--width`, `--input-only` and optional capture time let you state exactly what is being inspected. See [input diagnosis](../DIAGNOSTICS.md).

Reports distinguish configuration, evidence and fitted output by instance ID: missing or invalid fields, zero, identity mismatch, stale or partial observations, unknown freshness, conditions, clipping and width omission. Input time, source observation time and diagnosis time remain separate. No network query, transcript scan, collection, reconciliation, repair or snapshot write occurs. Existing editor Explain panels remain explicitly sample-only.

The existing `worktree` item now falls back from Claude's `worktree.name` to `workspace.git_worktree` for ordinary linked Git worktrees. Diagnosis identifies both sources. The new optional `cache-miss-reason` item shows the host's likely reason for the latest main-conversation cache miss; detailed tool counts, system-prompt character changes and event time are in diagnosis. Known causes support all six languages and unknown codes remain readable. The official cache hit ratio and PR/MR behavior are unchanged.

Upgrade with `npm install --global --ignore-scripts @fbincon/claude-code-statusline@3.3.0`, run `claude-statusline install`, then restart Claude Code. Node 22/24 remain supported. Editor protocol is **14**; display schema **8**, runtime protocol **2**, portable **1** and UI preferences **1** remain unchanged. Reinstall matching frontend/backend resources. Before downgrading, remove `cache-miss-reason` from saved configuration or restore an older backup.

The [v3.3.0-only decision](approvals/v3.3.0.json), approved on 2026-10-20, accepts six existing gaps while requiring all automated gates to pass. Historical physical/desktop/exact-declaration gaps in [#96](https://github.com/fbincon/claude-code-statusline/issues/96) remain unverified; no new functional failure is waived. See [implementation and validation](../development/real-input-diagnostics.md) for actual delivery status and artifact identities. Existing beta and Python rollback artifacts are retained.

使用 `claude-statusline diagnose --input FILE|-`，按已保存的显示配置及可归属的既有观测检查显式提供的状态栏 JSON。CLI 提供本地化文本和 `--json` 报告，只读后端也支持未保存草稿。可通过 `--scope`、`--width`、`--input-only` 和可选采集时间明确诊断范围，详见[输入诊断](../DIAGNOSTICS.zh-CN.md)。

报告按实例 ID 分别解释配置、证据和拟合输出，区分字段缺失／无效、零值、身份不符、陈旧／部分观测、新鲜度未知、条件隐藏、截断及宽度省略。输入时间、来源观测时间和诊断时间独立记录。不执行网络查询、转录扫描、采集、协调、修复或快照写入，编辑器 Explain 面板继续明确解释示例。

既有 `worktree` 项在缺少 Claude 会话 `worktree.name` 时，回退到普通 linked Git worktree 的 `workspace.git_worktree`，诊断分别标明两个来源。新增默认关闭的 `cache-miss-reason` 项，显示宿主判断的主会话最近一次缓存未命中的可能原因；详细工具数量、系统提示字符变化及事件时间放在诊断中。六语言覆盖已知原因，未知码保持可读，官方缓存命中率和 PR/MR 行为不变。

运行 `npm install --global --ignore-scripts @fbincon/claude-code-statusline@3.3.0` 后执行 `claude-statusline install` 并重启 Claude Code。继续支持 Node 22/24。编辑器协议为 **14**，显示 schema **8**、runtime **2**、portable **1**、UI preferences **1** 不变，升级后须安装匹配的前后端资源。降级前移除保存配置中的 `cache-miss-reason`，或恢复旧配置备份。

2026-10-20 批准的 [v3.3.0 专属决定](approvals/v3.3.0.json)仅接受六项既有缺口，仍要求自动化门禁全部通过。[#96](https://github.com/fbincon/claude-code-statusline/issues/96) 的历史实机／桌面／精确宿主声明缺口仍未验证，不豁免任何新增功能失败。实际交付状态和产物身份见[实现与验收](../development/real-input-diagnostics.zh-CN.md)，保留既有 beta 和 Python 回退产物。

# v1.8.0 — English and Simplified Chinese interfaces

Configure the tool in **English / 简体中文** through the in-session Client, external/standalone terminal editor and CLI. English remains the default. Language switches save immediately while preserving the current page, selection, search, input and unsaved display draft.

## Install or upgrade

```text
pipx install --force fbincon-claude-code-statusline==1.8.0
claude-statusline install --dry-run
claude-statusline install
claude-statusline doctor
claude-statusline config language set zh-CN
```

Restart Claude Code after refreshing integration. Existing display settings, editor/runtime enablement and language preferences are retained. The import package and CLI remain `claude_statusline` and `claude-statusline`. Older distribution-name installations use the [migration guide](../USER_GUIDE.md#migrate-the-previous-distribution-name).

## Language behavior

- Settings includes **Interface language (saved immediately)**, with recognizable English / 简体中文 choices. Cancelling display edits keeps the language; a failed language write keeps the prior view. Other open windows read the preference when reopened/reloaded. Both editors search IDs, English/Chinese names/descriptions and custom labels.
- `config language show [--json]`, `set en|zh-CN` and `reset` manage `<CLAUDE_CONFIG_DIR>/statusline-ui.json` (schema v1). Missing/invalid reads fall back to English without repairing the file; explicit writes back up repairs and reject future schemas. Normal reinstall, upgrades and uninstall preserve it.
- Root `--language en|zh-CN` precedes the command, overrides the saved preference only for that invocation and controls the initial `configure` language. CLI help, groups, parameter errors and tool-owned administration/diagnostics use the selected language.
- Menu/group/item names, descriptions, choices, forms, shortcuts, progress and results are translated. Existing hotkeys, commands, persisted values, IDs, model names, paths, branches and custom input remain intact. Actual statusline output and sample content retain existing wording; machine-readable catalogs remain English.

## Architecture and compatibility

Python owns the two JSON language packs; generated TypeScript reuses them. Resource checks require matching keys/placeholders, valid control characters and synchronized packaged data. Semantic messages retain canonical English diagnostics plus keys/parameters for presentation and recovery decisions.

Configuration protocol advances from v4 to **v5**, adding `read_ui_preferences`, `set_ui_language` and error localization metadata. Reinstall matching native/backend resources after upgrading. **Display schema v5 and runtime protocol v2 remain unchanged.** Existing historical display files, revision conflicts, portable files, renderer output and lazy startup paths retain compatibility. The language is independent of display drafts, presets, import/export and revision values. See [language usage](../USER_GUIDE.md#interface-language), [translation contributions](../development/i18n.md) and [protocol](../development/contracts.md).

## Validation and publication

Implementation validation passed **680 Python tests** (672 passes, eight expected platform skips), **71 native and ten runtime official Mod tests**, both TypeScript projects, generated contracts/resources, Ruff and bilingual documentation checks. Each language contains 932 matching keys. Tests include fallback/repair/future protection, write failure/concurrency, CLI overrides/help/errors, draft preservation, bilingual search, custom labels, Unicode and native 32×12/external 64×18 layout bounds.

A fixed-commit installed wheel passed real Linux x86_64 / CPython 3.14.4 / Claude Code 2.1.295 language PTYs: external 64×18, 64×20, 80×24, 120×30, 80×48; persistent native 120×30 and 80×48. Complete advanced two-editor checks cover forms, layout, presets, import/export, Claude preference Apply/reload, saves and cancellation. Core/native/runtime installation checks passed. [Ten bilingual images](../images/README.md#bilingual-terminal-captures) reconstruct actual captured cells: native multiplexer output uses an explicit light surface and host-quantized 256 colors; direct theme PTYs separately verified RGB. Agent capture inspection is recorded independently of human acceptance.

Publication requires all 23 cross-platform jobs on the PR, merge and tag, fixed-merge wheel/sdist/checksums, independent rebuild/install and upgrade acceptance, verified draft/public bytes, TestPyPI acceptance, formal PyPI index installations, and identical GitHub/Gitee attachments. This version uses local commands and fixed samples without paid model calls. It preserves the documented [macOS Client focus limitation](../USER_GUIDE.md#macos-mouse-reporting-and-client-focus); new human and Windows/macOS terminal language acceptance are not claimed. Historical human acceptance and release records remain intact.

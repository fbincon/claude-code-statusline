## 共同设计约定

- **保持定位：**状态栏负责清楚呈现任务、代理、项目和用量；详情与解释使用既有按需入口。保留真实零值及缺失、过期、部分、不支持等不同状态，不推断没有证据的任务结果。
- **共享实现：**core 保存纯配置、目录、Unicode、布局与解释规则；platform 负责文件、进程和终端；cli 编排服务；tui 与原生 Mod 适配交互。复用既有事务和任务存储。[当前架构](architecture.zh-CN.md)。
- **配置边界：**界面语言立即保存，显示语言和外观随显示 Save 保存，Claude 宿主偏好独立 Apply。预览、导入审阅和方案选择只产生候选草稿。用户级默认、命名方案和项目编辑目标始终可辨认。[方案语义](../PROFILES.zh-CN.md)。
- **兼容：**当前基线为显示 schema 16、编辑器协议 27、来源注册表 2／任务 3、来源观测 1、runtime 3、lifecycle 4、portable 1、UI preferences 1、方案集合／导出 1，各接口独立演进。先列明新增字段和旧数据解释，再决定具体版本；旧文件读取不静默写回，实际迁移沿用备份和恢复机制。
- **扩展授权：**默认使用宿主输入及本地状态。外部文件源、联网提供方和命令分别启用，按用户配置登记。显示方案可以引用来源，但导入、预设选择和项目绑定不能授予执行或联网能力。
- **范围界限：**正式后续以上表为准。既有 setup、选择性导入、静态组件渐变、显式行对齐、GitHub 自动刷新及 CLI 版本管理保持已交付。其他提供方、数据及较远方向按[候选池](roadmap.zh-CN.md#candidates)进入条件另行决定。全局外观复用沿用既有导入，组件样式与组复用归 IMPORT-02。
- **未来接口：**先写清配置意图、数据流与兼容，再分配未来 schema／协议版本或公开命令名称。复用组件能力目录及生成的编辑器资源；新增选项须贯穿预览、保存／重开、方案选择、导入导出与冲突处理，读取旧配置不会开启新行为。
- **Native 展示：**保留 v3.9.1 的宿主持有完整状态及有界可见帧。新管理器、任务详情、历史和预览分别约束输出 props、外层 Pane 与 Client 树，包括直接使用 Pane 的路径。保留分页、选中内容、完整字素和彩色预览，缩减展示而不裁剪存储配置。恢复入口位于可能被拒绝的树之外，保留草稿并区分保存成功、进行中和未知结果。沿用既有[容量与恢复](native-capacity.zh-CN.md)规则及适用的实际宿主覆盖。
- **两端能力：**双编辑器共享业务规则和主要能力，布局与控件按平台适配。长列表／详情分页，库、候选草稿和撤销历史留在宿主。只读页面和审阅保留各自的无副作用边界。
- **针对性验证：**按受影响规则选择变更用户流程与相邻组合，扩充现有套件，不要求每个切片新增完整流程、独立 PR 或笛卡尔积矩阵。Ready 产品 PR 与候选晋级沿用当前 [CI 要求](ci-maintenance.zh-CN.md)，本次规划不修改验收策略。

## FIX-01 保存未知态的草稿保护

**目标与范围。** 防止待核对保存结果覆盖期间发生的显示修改。来源／状态只读查看可以保留，所有显示修改统一经过权限规则，覆盖子页面、快捷键与按钮。来源授权和宿主 Apply 保留各自提交语义。

**职责与兼容。** Core 管理草稿修改守卫，Native hooks 管理待确认保存身份和只读核对。共享来源／方案／导入／分组／对齐编辑及适用的外部恢复遵守同一规则。保留提交快照、revision、锁和备份，不预设显示格式变化。

**切片。** 清点显示修改入口 → 集中守卫并接通调用者 → 验证核对及结果明确后的继续编辑。

**验收。** 未知态阻止绑定／解绑、草稿替换和结构修改，包括已打开的管理器入口。覆盖已经保存、未提交、并发冲突及仍未知的回读；查看仍可用，恢复／重试不重复写入或抹除保留草稿。在既有套件中增加适用的 Native 交互回归。

**交付：**v3.9.2 已完成，接口、回归与渠道证据见[正确性修复记录](correctness-maintenance.zh-CN.md)。

## FIX-02 进度条与标签统一组合

**目标与范围。** 主栏和子代理图形指标只执行一次标签规则。先组织进度条、标签、数字及已用／剩余含义，再统一修饰，不从条形前缀字符串中反向识别标签。

**职责与兼容。** Core 渲染／格式化拥有组合规则，CLI 与双编辑器共同使用。保留现有数字／进度条选项、指标口径、阈值、明确零值及缺失语义；自适应拟合属于独立 APPEARANCE-07。

**切片。** 固定数字／进度条的预期标签 → 修复共享组合 → 增加主栏／子代理针对性回归。

**验收。** 覆盖既有、隐藏、短、自定义标签与图标、阈值及六语言组合。断言百分比／方向保留、标签不重复、字素与颜色重置完整，并遵守既有宽度；仅宽度断言不能证明文字含义正确。

**交付：**v3.9.2 已完成，接口、回归与渠道证据见[正确性修复记录](correctness-maintenance.zh-CN.md)。

## FIX-03 刷新执行与等待使用者分离

**目标与范围。** 区分共享刷新任务和等待它的编辑器、CLI、自动策略。离开或中断一个入口只释放自己的使用关系。主动终止整个任务是独立操作，只有最后一个适用使用关系消失后才取消已无需要的执行。

**职责与兼容。** Cli 来源服务管理持久执行／使用关系生命周期，platform 处理进程终止，core 契约和共享管理器表达加入／释放／状态。变更来源任务接口前明确旧任务解释和迁移，保留来源修订、上下文身份及自动／手动归属。

**切片。** 定义持有关系和最后使用者规则 → 更新服务、编辑器关闭及 CLI 信号路径 → 验证手动／自动重叠与到期。

**验收。** 覆盖两个编辑器、编辑器与 CLI、手动与自动刷新共享身份。一个退出不影响另一个；最后使用关系释放、显式取消、来源停用／修改和续租到期结果不同且可解释。迟到结果不能发布到其他修订或上下文。

**交付：**v3.9.2 已完成，接口、回归与渠道证据见[正确性修复记录](correctness-maintenance.zh-CN.md)。

<a id="fix-04"></a>

## FIX-04 扩展诊断的时间与代理适用性

**目标与范围。** 扩展值及附加字段遵守给定输入的观测时间；历史重建排除较晚证据，无时间戳保持未知。按组件实例／代理身份保留每份证据，不再只按实例 ID 覆盖。

**职责与兼容。** Cli 观测适配与 core 诊断复用时间／状态规则。实时渲染和显式历史诊断分别处理，输入时间与诊断时间独立。扩展诊断结果接口时审查已有消费者兼容。

**切片。** 定义适用性及证据身份 → 过滤来源视图、累积代理证据 → 同时验证渲染与机器可读解释。

**验收。** 覆盖更早／相同／较晚／未知时间、过期和部分数据、零值、多个代理复用组件及不同组件副本。较晚的值或 PR／检查附加字段不能影响历史输出或成为当前证据。仅输入诊断继续只读且不读取来源。

**接口与兼容。** 保留既有显示项 ID、状态含义和来源身份，不预设需要新用户命令或显示 schema。修正前说明仓库本地／用户级配置、已知过滤器兼容及间接 Git 环境的处理。按选定策略无法采集时保留明确不可用原因，不显示成正常零值或干净状态。

**功能验收。** 覆盖仓库控制的 fsmonitor／过滤器、local／worktree 与 global／system 设置、已知过滤器、间接提供方调用、裸仓库及 linked worktree、中文空格路径、调用失败和普通干净／有修改仓库。证明选定策略阻止非预期程序执行、保持支持的指标语义且不修改仓库／用户配置。核查结论与实际修复的缺陷分别记录。

## 实施交接与文档维护

开始具体工作包时记录：当时 main、选定范围、涉及模块、配置／协议决定和首个可交付切片。每个工作包保留用户问题、预期流程、首版边界、模块职责、接口／兼容影响、切片及完成证据。实施中的范围变化回写本计划及双语路线；新功能的使用文档与实现同步维护，不提前宣称可用。

交接记录至少包含：工作包及状态、已完成切片、剩余问题、源码／PR 身份、验证命令和结果、下一步。状态顺序为 `NOT_STARTED` → `IN_PROGRESS` → `VALIDATING` → `DONE`；工作包完成与版本发布分别记录，已合并的小切片不代表整包完成。版本发布时再附产物及渠道证据。

[路线图](roadmap.zh-CN.md)维护优先级与状态，本计划维护范围与验收。两者均为公开仓库文档，并维护完整英文对照；本地历史快照与原始校验记录分别保留，公开导航不能依赖这些文件。迁移阶段状态继续由[重构计划](typescript-migration.zh-CN.md)维护，功能交付证据由对应的实现记录维护。

文档验收核对六份双语规划／索引文件的任务 ID、顺序、依赖、路线图维护的状态、切片覆盖及导航，核对已交付事实、链接与锚点；执行 `npm run docs:check` 和 `git diff --check`，并在仅含已提交文件的检出目录执行文档检查。记录文档验证结果，不据此宣称未来功能已经通过验收。本次仅规划更新不修改产品 README、稳定版指南、发布记录、生成资源或代码。

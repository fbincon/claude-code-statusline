## 共同设计约定

- **保持定位：**状态栏负责清楚呈现任务、代理、项目和用量；详情与解释使用既有按需入口。保留真实零值及缺失、过期、部分、不支持等不同状态，不推断没有证据的任务结果。
- **共享实现：**core 保存纯配置、目录、Unicode、布局与解释规则；platform 负责文件、进程和终端；cli 编排服务；tui 与原生 Mod 适配交互。复用既有事务和任务存储。[当前架构](architecture.zh-CN.md)。
- **配置边界：**界面语言立即保存，显示语言和外观随显示 Save 保存，Claude 宿主偏好独立 Apply。预览、导入审阅和方案选择只产生候选草稿。用户级默认、命名方案和项目编辑目标始终可辨认。[方案语义](../PROFILES.zh-CN.md)。
- **兼容：**当前基线为显示 schema 13、编辑器协议 21、来源注册表／任务 2、来源观测 1、runtime 3、lifecycle 4、portable 1、UI preferences 1、方案集合／导出 1，各接口独立演进。先列明新增字段和旧数据解释，再决定具体版本；旧文件读取不静默写回，实际迁移沿用备份和恢复机制。
- **扩展授权：**默认使用宿主输入及本地状态。外部文件源、联网提供方和命令分别启用，按用户配置登记。显示方案可以引用来源，但导入、预设选择和项目绑定不能授予执行或联网能力。
- **范围界限：**先完成选定工作包的具体流程。选择性导入、静态前景／Powerline 背景渐变及主栏显式行对齐已有独立工作包。其他数据、配套及较远方向按[候选池](roadmap.zh-CN.md#candidates)的进入条件单独决定。既有 setup、GitHub PR／CI 及刷新、缓存视图和 CI 维护均为已交付能力，不是新缺口。
- **未来接口：**先写清配置意图、数据流与兼容，再分配未来 schema／协议版本或公开命令名称。复用组件能力目录及生成的编辑器资源；新增选项须贯穿预览、保存／重开、方案选择、导入导出与冲突处理，读取旧配置不会开启新行为。

## GIT-01 Git 调用核查与必要防护

**状态：DONE。** 从 `d2975e8` 启动，目标为 v3.8.0。共享调用策略已实现；平台及安装产物验收记录在[交付记录](m8-m9-delivery.zh-CN.md)。

**已有观察与限制。** 2026-10-24，在 Linux、Git 2.53.0、Node 24.21.0 下，以临时仓库调用[实施前的 GitCollector](https://github.com/fbincon/claude-code-statusline/blob/d3c95232a18cb297bbd836c4deda117749e90ee4/packages/cli/src/runtime/git.ts)。仓库级 `core.fsmonitor` 触发了无害标记程序；受跟踪文件改变内容但长度不变时，本机 clean filter 也触发标记，而改变长度的测试场景没有触发。对照调用显式关闭相应设置后不再触发，仓库配置字节保持不变。选择防护策略前应复现这些条件。该观察不说明普通 clone 会传入本地配置，也未覆盖全部 worktree／bare 仓库、过滤器、间接提供方调用和 Windows／macOS 行为，历史观察与上方当前实施状态分别记录。

**问题与目标。** 以字面参数调用 Git，不足以决定 Git 是否会按仓库配置启动其他程序。核实当前采集实际执行的行为，在不改变指标含义、不修改用户仓库的前提下修正已证实缺口。

**范围与流程。** 清点直接 Git 调用及提供方工具间接调用的 Git，核查 fsmonitor、local／worktree 过滤器命令与向上发现裸仓库的行为。在隔离夹具中比较当前行为和拟议调用策略，记录是否需要修改，再实施必要防护。通过明确兼容表保留正常 Git LFS 及其他支持的用户过滤器，不笼统关闭所有 global／system 设置，不放宽 Git 所有权检查。

**数据与模块。** 从 [GitCollector](../../packages/cli/src/runtime/git.ts)、cli 来源上下文／提供方编排及 platform 进程适配开始。受影响入口共用调用策略，解析和指标渲染继续留在 core。诊断明确不可用／被阻止结果，不暴露凭据、不在真实仓库运行测试程序、不改写 `.git/config`。

**接口与兼容。** 保留既有显示项 ID、状态含义和来源身份，不预设需要新用户命令或显示 schema。修正前说明仓库本地／用户级配置、已知过滤器兼容及间接 Git 环境的处理。按选定策略无法采集时保留明确不可用原因，不显示成正常零值或干净状态。

**实施切片。** 清点与隔离复现 → 行为／兼容表 → 必要时实现共享策略及调用点调整 → 回归和诊断说明。认定无需修改时也须保留复现及理由。

**功能验收。** 覆盖仓库控制的 fsmonitor／过滤器、local／worktree 与 global／system 设置、已知过滤器、间接提供方调用、裸仓库及 linked worktree、中文空格路径、调用失败和普通干净／有修改仓库。证明选定策略阻止非预期程序执行、保持支持的指标语义且不修改仓库／用户配置。核查结论与实际修复的缺陷分别记录。

## TERMINAL-01 Windows 预览一致性

**状态：DONE。** 优先独立维护，跟踪 [Issue #130](https://github.com/fbincon/claude-code-statusline/issues/130)。

**问题与目标。** 问题报告指出，同一 Windows 终端中，setup、独立 configure 和 slash 启动的外部编辑器预览颜色不同。基线的[色深判断函数](https://github.com/fbincon/claude-code-statusline/blob/d2975e8a4561371b5d32bec136400963dbccd97f/packages/tui/src/session.ts)仅有 Windows Terminal 标记时返回 16，有 `TERM=xterm-256color` 时返回 256；这一纯函数观察不等于新完成的 Windows 桌面验证。相同终端应获得一致的能力判断，确实存在的受支持差异则准确说明。

**范围与流程。** 使用同一安装包和显示配置复现三个入口，辨认环境与控制台差异，修正或说明能力选择，再重开各入口对比预览和实际输出。保留显式 `NO_COLOR`、单色终端及用户能力选择。原生编辑器的主题行为属于另一界面，不要求模仿外部 TUI 颜色。

**数据与模块。** Tui 管理共用预览／会话判断，platform 管理终端／控制台能力及环境传递，cli 管理启动编排，core 保留共用颜色转换和 Unicode 渲染。复用一套能力策略，不在各入口独立设置默认值。

**接口与兼容。** 不预设显示迁移或新命令。保留已保存的外观、语言、来源授权和宿主设置；能力依据不可用时如实说明，不声称支持未经确认的颜色模式。面向用户的指引覆盖六语言。

**实施切片。** 安装版 Windows 复现 → 共用能力／入口策略 → 有针对性的修正与回归 → 受支持行为及画面证据。

**功能验收。** 覆盖 Windows Terminal 与受支持控制台、PowerShell／CMD／Git Bash 入口环境、未设置／显式颜色变量、无色／单色及三个入口。验证调整窗口、取消、终端恢复、保存／重开，以及相同配置下的预览／实际输出。纯测试与真实 Windows 画面互补，未验证案例如实记录；结果用于 APPEARANCE-04、COMPOSITION-03 和 SHOWCASE-01 验收。

## SETUP-02 首次入口与持久安装

**状态：DONE。** M8，扩展已交付的 SETUP-01。

**问题与目标。** 已有 setup 串联配置和接入，但获取软件包和选择初始命令仍是分离步骤。提供无参数／npx 首次入口，连接持久安装与已有 setup 流程。

**范围与流程。** 在交互终端中检查当前软件包、Node／npm、全局 prefix、权限和已有接入；显示精确目标版本与持久位置；需要时明确批准由产品管理的 npm 全局安装；核验可执行入口后转入已有 setup。npm 最初为 npx 下载软件包，是独立于产品管理安装的步骤。复用匹配的持久安装，不静默升级或降级不同版本的已有安装。非 TTY 入口不得等待交互或修改安装／配置，应给出可操作指引。

**数据与模块。** Cli 协调入口分派、安装身份及 setup；platform 提供程序／prefix／权限检查和字面进程参数；core／tui 提供共用审阅状态及本地化指引。复用安装所有权、锁、journal 与备份，不将 Claude 绑定到可清理的 npx 缓存路径，也不以独立托管版本目录替代默认安装策略。

**接口与兼容。** 无参数行为是拟议的未来公共变化，既有显式命令保留含义。包安装、显示 Save、Claude 接入分别标明提交点。不自动提权、登录账号或启用采集。保留既有偏好、方案、项目绑定及独立关闭选择；某阶段完成后取消，应说明已完成阶段，不承诺整个流程回滚。

**实施切片。** 入口／安装身份与审阅契约 → 精确版本全局安装及持久入口交接 → 已有 setup 接入与失败指引 → 跨平台安装版完整流程。

**功能验收。** 覆盖新安装、相同／不同已装版本、多个 prefix、安装后清理 npx 缓存、prefix 不可写、工具缺失、非 TTY、中文／空格路径、取消、中断和网络／npm 失败。接入前重查所有权与 revision，保留可恢复的部分结果及无关用户设置。验证重启后的持久入口和实际显示，并与固定预览区分；受支持平台提供六语言指引。

## UPDATE-01 显式升级与回滚

**状态：DONE。** M9，使用 SETUP-02 的安装身份及既有兼容／恢复规则。

**问题与目标。** 让用户查看可用版本，主动升级或返回旧版，并区分软件包和配置的恢复结果。

**范围与流程。** 用户主动检查版本元数据，显示已装／目标身份与兼容性。改变版本前审阅精确选定版本及 npm 全局目标；核验新包及匹配接入资源后才报告成功。保留旧版本身份与适用配置备份。回滚先审阅目标版本和配置兼容性：兼容的当前设置保留，恢复旧快照则单独审阅哪些内容会被替换。

**数据与模块。** Cli 编排 registry 检查、版本选择、包切换及接入／恢复；platform 管理有界 npm 执行及安装检查；core 管理审阅／兼容结果和本地化解释。复用既有恢复 journal 与所有权规则，区分外部 npm 结果和配置提交。

**接口与兼容。** 实现时确定管理接口，不将拟议命令写成当前已可用命令。检查、升级和回滚均由用户显式触发，渲染及预览不查询或应用更新。不静默切换发布渠道、提权、手改版本号降级 schema，或覆盖更新后的用户修改。修改前识别不支持的 Node／宿主／配置组合并解释受支持恢复方法；npm 结果不确定时先检查，再决定重试。

**实施切片。** 只读版本／兼容审阅 → 显式升级与安装版验证 → 版本回退及独立审阅的配置恢复 → 中断／并发恢复和指引。

**功能验收。** 覆盖当前／可用／不可用版本、异常或失败元数据、精确版本选择、权限、支持及不支持的运行时／宿主组合、包成功但接入失败、中断和重试。覆盖配置兼容／不兼容的回滚、备份后的用户修改、缺失备份和并发编辑器。核对方案／绑定／关闭偏好、匹配资源、重启／实际显示及真实的部分结果；包替换与配置恢复分别提供证据。

## IMPORT-01 选择性配置复用

**状态：IN_PROGRESS。** M10，两个必需切片：先全局外观，再完整显示分区。

**问题与目标。** 用户应能复用选定外观或显示区域，不替换无关配置，也不丢失实例／分组关系。

## COMMAND-01 用户显式配置的命令组件

**已在 v3.6.0 交付 — DONE。** 本节保留历史范围与验收意图；当前使用方式见[扩展指南](../EXTENSIONS.zh-CN.md)，已验证行为与限制见[交付证据](extensions.zh-CN.md)。

**问题与目标。** 本地 JSON 之外，用户可能希望调用自己维护的工具生成展示值。命令结果仍进入统一来源契约，不改变官方指标。

**首版范围。** 使用明确的可执行文件、参数数组、工作目录和输入字段映射；默认不通过 Shell 解释。由独立刷新调用执行并发布观测，主／子状态栏只读取结果；预览不启动程序。支持约定的 JSON 输出或净化后的单行文字。通用 Shell、脚本下载和自动安装工具属于后续候选。

**启用与交互。** 本机来源配置展示完整程序、参数、工作目录和将提供的输入字段；用户明确启用后生效。默认输入只包含所选结构化字段，不自动传递会话正文、transcript 内容或凭据。导入的显示方案只能留下未绑定引用，不能引入已启用命令；修改程序／参数／输入范围后重新审阅。用户可以单独停用或删除来源。

**模块与接口。** 依赖 EXTENSIONS-01。platform 的 [进程适配](../../packages/platform/src/command.ts)处理参数字面量、结束与取消，cli 处理执行和观测发布，core 处理输出类型及终端文字净化。固定执行截止、输出边界和子进程结束语义，明确终止与非零退出结果；不直接复用任意 Shell 拼接。执行配置独立于可分享显示配置。

**原实施切片。**

1. 固定输入／输出和本机启用契约。
2. 实现进程、取消、失败与观测发布。
3. 接入来源审阅、诊断和组件配置。
4. 验证跨平台参数、导入和禁用流程。

**原验收标准。** 空格／中文／引号及特殊字符按字面量传递；缺少程序、非零退出、非法输出、超量输出、截止终止、后代进程保留管道、刷新取消和禁用都有明确结果。终端控制字符不能改变界面结构；旧来源结果不冒充当前成功。证据包含隔离进程用例、授权启停／导入用例和六语言错误展示。

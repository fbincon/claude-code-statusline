## 启动后待制定的工作

1. 对最终已安装 TS 候选运行原 D06 场景，记录源码、发行物、运行时、策略和夹具哈希，
   同时核对输出和精确采集次数。
2. 重新评估完整产品的实际瓶颈。现有线索包括中型冷缓存 RSS、热读／追加延迟、启动与 hook、
   Git 未命中／过期和多 Agent／Unicode 渲染。优先级由最终产品测量决定，当前合成 profile
   不能直接证明未来用户体验。
3. 在单独的实施任务中确定有界优化轮次及验收安排。每个候选均保持兼容性并逐项检查退化；
   不得使用仅适用于不确定结果的噪声例外，对已有失败的同一候选原样复测。

PERF-01 完成须满足其记录的性能目标和适用功能／平台检查。在此之前，所有未解决的失败或
不确定项继续明确保留。诊断采样与夹具验证不能替代性能通过结论。

## 迁移期间的边界

相对 Python 的延迟或 RSS 退化不阻塞 TS-03～TS-06，包括预览与正式交付。
这些阶段不要求重复执行完整 D06；发布说明须披露已知限制及恢复方式。

功能故障仍须处理：宿主超时导致操作无法完成、事件丢失、保存失败或内存耗尽等不能延期豁免。
保留现有超时、资源有界、锁、原子写、时钟精度和采集次数契约。
实体机／桌面验收及安装／恢复要求继续按迁移计划执行。

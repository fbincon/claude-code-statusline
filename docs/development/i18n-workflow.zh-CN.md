<a id="support-policy"></a>

## 支持政策

英语继续作为源语言与回退语言。全部包含的语言随同一 npm 包分发，离线可用；文档仍维护英文／简体中文。本项工作不引入语言下载器、翻译服务、市场或独立语言包。

| 等级 | 语言 | 开发期间 | 公开发布前 |
| --- | --- | --- | --- |
| A：核心 | `en`、`zh-CN` | 变更同时维护完整当前消息及适用验证 | 对应当前源文案，完整、安全且已接受 |
| B：官方完整支持 | `zh-TW`、`zh-HK`、`ja`、`ko`、`es`、`fr`、`de`、`pt-BR`、`ru`、`id` | 缺译、过期或待核验项可使用当前英语 | 当前必需条目全部已接受；无缺译／过期／待核验项，也无缺译回退 |
| C：社区／预览 | 仅限未来明确登记的语言 | 允许安全英语回退 | 披露接受覆盖率、待核验／过期项与回退；全部有效消息仍须安全 |

不得为解除发布阻塞，将已注册 B 语言静默降为 C。支持等级与填满多少键是不同概念。I18N-02 原范围不选择新增语言或文字系统；后续增加时须明确维护范围及相关功能验收。

工作流在已授权任务内完成翻译、上下文核对、适用检查和记录更新。验证生成只读回执，显式 `accept` 更新匹配的接受记录，不新增审阅角色、签字或独立批准步骤。如实记录实际验证范围，包括适用的术语和语义核对；结构检查不能证明语言质量。涉及破坏性操作、恢复、授权和数值含义的消息重点核对上下文，普通文案可以批量处理。

<a id="translation-state"></a>

## 翻译状态与有效消息

分别判断存在性、安全性、源版本一致性与接受状态。非英语条目的有效资源使用当前已接受译文，否则使用当前英文模板；英语本身必须完整、安全。不得为满足覆盖率而向原始语言包机械填入英文。命令或技术术语的译文有意与英文相同，可以合法并被接受。

| 状态 | 含义 | 有效输出与门槛 |
| --- | --- | --- |
| `accepted` | 源签名、译文哈希与适用接受记录匹配 | 使用译文，保留具体接受方式 |
| `missing` | 必需源键没有译文 | 使用英语；A 开发门槛及 A／B 发布门槛失败 |
| `stale` | 原文或语义契约改变 | 旧条目保留供修订，使用当前英语；A 开发门槛及 A／B 发布门槛失败 |
| `pending_validation` | 译文面向当前源，但所需检查或记录未完成 | 在同一流程完成检查与记录，接受前使用英语；A 开发门槛及 A／B 发布门槛失败 |
| `obsolete` | 已退役键具有可验证历史来源 | 排除于当前资源和覆盖率分母，单独保留为历史 |
| `invalid` | 当前／新内容有非法类型、模板、不安全文本或无来源的多余键 | 校验失败，不以回退掩盖非法提交 |

每条接受记录绑定稳定键、源签名、译文哈希和接受方式。源签名覆盖英文、命名占位符契约及影响含义的上下文版本；英文未变但含义变化时，须更新上下文版本或使用新语义键。术语变化只使关联条目失效，不使无关译文全部过期。

签名采用版本化、确定的编码与排序，不能裁剪或规范化掉有意义的变化。时间及执行引用可记录核验过程，但时钟、网络和遍历顺序不能改变运行资源。即使英文未变，译文修改也会使旧接受失效。

首个功能交付同时处理四类源变更：

| 变更 | 必需处理 |
| --- | --- |
| 新增键 | 非核心语言未翻译的条目标为缺译，生成当前英语回退 |
| 原文改义 | 旧接受失效，重新核验前使用当前英语 |
| 占位符变化 | 有来源的旧模板按旧契约隔离；拒绝新提交的不匹配模板；运行产物只包含符合当前契约的模板 |
| 删除键 | 有来源的旧条目退役，不生成已退役键；拒绝无说明的多余键或拼写错误 |

历史隔离要求条目未经改写，且受版本控制的输入提供可验证的旧接受身份／契约；生成时不得依赖完整 Git 历史或联网查询。历史内容仍须通过 JSON 解析、重复键及文本安全检查。仅放宽缺键完整性，无法识别含义过期，也无法证明多余键或旧占位符契约具有有效历史来源。

报告分别统计原始存在、当前有效译文、已接受译文、缺译／过期／待核验／无效项及有效英语回退。生成结果的键齐全不等于翻译接受率 100%。首次迁移只在输入匹配且旧证据可验证时使用 `baseline_accepted`，保留原有实际范围与限制；否则核验当前输入并记录 `validated_accepted`。不虚构过去的审校，也不因元数据是新的就重跑已被有效覆盖的检查。

<a id="ownership"></a>

## 资源归属与接口

| 输入或使用方 | 职责 |
| --- | --- |
| `packages/core/resources/i18n/languages.json` | 规范语言代码顺序与原生名称；当前 schema 仅接受 `code`、`name` |
| `packages/core/resources/i18n/locales/*.json` | 真实原始译文，不混入接受记录或机械英文填充 |
| 构建专用政策、上下文、术语及按语言分片的接受输入 | 独立于语言包发现和自动装包的 workspace resources；启用相关行为前登记归属与验证输入 |
| `tools/generation/resources.ts` | 统一分析源状态，派生确定的有效资源和报告，并检查相应门槛 |
| 共享 core 消息、搜索与渲染，以及生成的 Node／Native 副本 | 使用同一有效消息及必要来源信息；运行时不读取接受历史 |

当前[打包器](../../tools/build/pack.ts)递归复制 workspace 的 `resources`，因此构建专用元数据必须放在明确排除的位置，或具有显式打包规则，并通过包校验确认其未进入运行包。同时，它们仍须进入可复现源归档和适用的源码／报告输入身份。不要将元数据 JSON 放入 `locales/`，否则会被识别为语言包。

core 保持纯消息、搜索、Unicode 与渲染规则；platform 负责文件／进程／终端效果；CLI 编排服务；TUI 和 Native 适配交互。保留按语言拆分的状态栏模块及 Native 导入模块边界；状态栏渲染不得新增对 UI 词典或接受历史的依赖。不重新生成 Python 归档。

翻译指南维护已实现的开发命令。元数据与报告采用内部版本化接口，显示 schema 17／编辑器协议 30 保持不变。只在数据实际跨越接口时处理兼容；增加政策不自动要求迁移用户配置。保留历史 `sourceHashes()`、`policyDigest()` 的含义与回执身份，新输入须显式绑定并具有兼容读取器。

<a id="working-flow"></a>

## 开发、翻译与发布流程

1. **功能开发：**维护英中消息，立即识别所有受影响的译文状态，并生成所属副本。过期检测从源变化时开始，不等待后续冻结。
2. **组织翻译：**按需冻结源提交及目录、上下文、政策摘要，与可验证的前一输入比较，输出新增、原文变化、参数变化及删除清单。包含英文、简中参考、占位符、使用上下文、相关术语及适用单元格预算。源再次变化时生成新的冻结身份。
3. **验证与接受：**修订译文，完成适用检查与上下文核对，直接生成匹配的接受记录。原始输入与生成副本随同一次变更提交，副本重新生成而不手工合并。翻译可随功能工作完成，也可使用聚焦的维护 PR。
4. **发布：**对精确选定的资源要求当前 A／B 门槛和真实 C 披露。在任务内补齐缺译、过期、待核验或无效项，只重做受影响且不可复用的检查，不新增国际化批准步骤。

开发与发布共用同一生成规则，不能通过环境变量或发布生成模式使同一输入得到不同字节。开发候选可以具有合法的 B 语言回退而尚未达到语言发布条件；产品或维护验收通过，不能绕过任何发布路线上的语言门槛。

| 能力 | 与既有工具的衔接 |
| --- | --- |
| 开发检查 | 在现有生成／检查任务中加入 A 完整性、状态、安全及有效资源检查 |
| 报告 | 扩展覆盖率含义，区分原始、已接受与回退状态；机器可读和人可读报告来自同一分析 |
| 冻结／增量任务清单 | 读取固定输入，输出身份与清单；不修改译文或接受记录，不联网，不启动完整构建／测试 |
| 发布门槛 | 将 A／B 就绪和 C 披露接入既有候选／发布校验及已验证报告复用 |

上述能力现通过 `generate`、`generate:check`、`languages:coverage`、`check` 及[翻译指南](i18n.zh-CN.md#增量维护)中的开发专用 `languages` 子命令实现；`docs:check` 继续只验证文档。报告对源文案和接受记录只读，记录更新是工作流中的显式操作。复用分析和既有 artifact，不为四项能力增加四次重复 CI 执行。冻结、核对和补记录属于工作步骤，不是额外请求许可。

<a id="frontend-contracts"></a>

## 前端与 Native 契约

界面语言保持独立即时持久化，沿用写入失败行为并保留页面、选中项、搜索、输入和草稿。输出语言跟随显示草稿预览及 Save／Cancel，Claude 偏好仍独立 Apply。保留 `zh-Hant` 规范化、显式选择、只读配置加载、归属／修订检查、锁、备份及恢复，不引入系统语言自动选择。

生产与预览共享渲染规则，通过注入观测区分输入。保留外部错误原文、数字、单位、ID、路径、命令和用户标签。必需英语遗漏由开发检查阻断，不改变生产 render／hook 的静默失败或 JSON／NDJSON stdout。搜索使用相同有效文本与稳定匹配／排序；英语回退须保留英语来源，不能成为另一语言已翻译的证据。

沿用既有 [Native 展示边界](native-capacity.zh-CN.md#展示边界)：

- Host 保留完整编辑器、词典、索引、草稿、候选和历史。Client 仅接收可见的扁平 Box／Text frame 与必要原始属性；不把全语言、接受历史、报告或隐藏页面放入 props。
- props、外层 Pane 和 Client 绘制树分别预检，包括普通 Pane 路径。核验基线的预算是 48,000 个保守序列化字符、10,000 个值、深度 16，包含非 ASCII 转义膨胀；它们是内部安全预算，不是宿主硬上限或字节数。
- 保留字素安全投影、样式／空白合并、分页、选中内容和彩色生产预览。先减页高再减显示宽度，维持既有最小视口；缩减展示而不裁剪存储配置、译文或草稿。
- 最小视图仍不可表示时，使用被拒绝树之外的恢复入口。区分保存成功、进行中和未知结果；Retry 只重挂、不重存。未知写入保留既有只读核对与阻塞规则，沿用 epoch／generation 顺序、输入去重、缩放及晚到响应处理。

通过既有分片资源，保持 Native 导入模块低于当前宿主的 1 MiB 限制。将受影响的长文本、Unicode、窄／高视口和恢复场景纳入既有实际宿主套件。序列化预检、PTY 及重建截图本身不能证明宿主或实体机验收；本工作不要求每种语言分别执行完整宿主流程。

<a id="ci-routing"></a>

## CI 分类与 PR → main → tag 复用

使用既有 `ImpactPlan` 和受保护的 `Complete candidate evidence` 聚合；聚合名称不代表维护任务必须跑产品矩阵。[影响检查](impact-checks.zh-CN.md)与 [CI 维护](ci-maintenance.zh-CN.md)继续为准，新输入启用前完成登记及相应回归。

| 实际变化 | 预期职责与检查 |
| --- | --- |
| 普通规划／贡献文档 | 文档路线，以及既有的无条件 Action 身份检查 |
| 既有译文值变化，键／占位符不变且生成副本一致 | 既有 presentation 检查，包含受影响前端／宿主和包义务 |
| 报告工具、接受政策或元数据 | 按已登记的实际工具／政策／构建职责分类，检查有效运行产物影响，不能只相信文件名 |
| 生成、构建或打包规则 | 必需生成／构建检查与实际包比较；不等价的产品变化要求产品验收 |
| 首次回退／状态行为、运行逻辑、语言注册、键／占位符或默认值 | 在最终 ready PR 源码上完成产品验收 |
| 混合变更 | 适用检查取并集并去重 |
| 未知归属或比较未解决 | 阻止提升，完成分类／比较后继续；既不跳过，也不默认跑昂贵完整矩阵 |

必需语言报告绑定源消息、原始译文、接受／上下文／政策输入、生成器身份及实际验证结果，随相关既有 artifact 保存。允许开发回退前，兼容报告／schema 读取器和发布门槛必须工作，包括完整产品源提升与维护源发布。格式不兼容时，须按已接受基线的信任边界完成显式兼容验证，不能由新验证器自行认可自己的输出。

Ready 产品 PR 对最终源码执行一次所需完整验收，包含受影响语言案例；Ready 维护 PR 执行选定专项任务。等价 main 合并保留已接受第一父验证：完整产品源另执行既有三平台集成 smoke，维护源复用专项回执，不生成新产品候选。验证器代码来自真实已接受第一父版本，不能由恢复的候选编译产物替换。

完整产品源 tag 复用已验证原始字节与证据。维护源 tag 构建自己的包、源归档、清单和校验和，保留独立／源归档重建、已接受代码比较、三平台安装 smoke 及源绑定发布检查，并显式关联原始产品覆盖。通过匹配的报告或对确定输入的轻量核验确认当前语言就绪，不在 main／tag 重跑完整产品或语言矩阵。原报告的源码／执行身份保持原样，关联到新的提升／发布身份。

保留最新适用执行、最新 artifact 选择及过期／损坏检查。缺失、过期、失败或不兼容证据仍阻断，旧绿色结果和手动诊断不能替代；按现有路线只修复或刷新必要部分。保留当前逻辑平台／运行时／宿主及六语言覆盖，包括 36 种界面／输出组合，不将每个语言乘以全部宿主、平台和视口。不增加重复依赖安装、生成、构建或逐语言作业；普通文档维护不要求下载旧产品候选。

## 交付边界

下表保留 I18N-02 原始切片及六语基线；后续十二语言扩展不改写这些原始结果。

| 切片 | 交付与完成条件 |
| --- | --- |
| 1. 基线与兼容准备 | 记录实施起始源码、已有六语证据及限制；定义构建专用输入、归属、源归档／运行包边界、报告绑定和兼容验证。复用有效旧结果，仅在必要处建立当前记录；启用的输入不能留下未知归属。 |
| 2. 最小完整工作流 | 交付签名、接受失效、全部状态与四类源变更、历史隔离、统一有效资源和基础报告。同一交付边界接通 A 开发门槛、A／B 发布门槛和 PR／main／tag 验证路径。建立六语基线，不声称未执行的审校；安全 B 回退不能先于发布保护上线。 |
| 3. 维护工具与扩展入口 | 增量／冻结清单、批量验证和记录更新，以及适用术语／上下文支持；定义 C 披露及未来语言进入条件，不指定新语言。报告均可从声明输入复现，翻译维护按实际影响执行。 |

这些是依赖与验收边界，不强制拆成独立 PR 或重复完整矩阵。必要兼容工作必须早于行为启用；现有验证器能够独立核验时，兼容准备与功能工作可以同一交付。实施记录届时的精确接口与迁移决定，不增加单独设计批准步骤。

未来语言执行完整结构／模板／安全／生成检查，并覆盖其界面、输出、搜索及相关布局；发生影响时补充代表性的跨语言独立性案例。选定语言确有需要时，明确数量表达、短标签、复杂复数及 RTL／双向文字行为与宿主覆盖，填满字符串不能证明排版支持。本工作包不要求新格式框架或用户可选测试语言。

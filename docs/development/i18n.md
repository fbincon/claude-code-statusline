# Interface translation and contributions

**English** | [简体中文](i18n.zh-CN.md)

The English and Simplified Chinese interfaces share one set of semantic messages. Python owns the resource files; TypeScript consumes generated data. Follow the [development checks](README.md#run-checks) and [user language behavior](../USER_GUIDE.md#interface-language) when changing translations.

## Resource ownership

```text
src/claude_statusline/
  config/ui_preferences.py          Shared preference storage and transactions
  i18n/
    locales/en.json                Canonical English message keys
    locales/zh-CN.json             Matching Simplified Chinese translations
    translator.py                  Lazy messages, parameters and fallback
    argparse.py                    Per-parser help and error presentation
    presentation.py                Fields, choices and bilingual search
mods/statusline-native/lib/i18n/
  generated-locales.ts             Generated; never edit by hand
  index.ts                        Explicit-language translation and wire validation
  messages.ts                     Semantic messages through frozen Client ports
  presentation.ts                 Translated labels, choices and shortcuts
tools/generate_i18n.py             Validation and deterministic generation
tests/i18n/                       Resource and fallback tests
tests/ui/test_language.py          External editor language behavior
tests/integration/test_language_cli.py
mods/statusline-native/tests/integration/language.test.ts
```

The supported codes are `en` and `zh-CN`; English is the fallback. Every supported locale must have exactly the English keys. Keys identify meaning and should survive wording changes; reuse a key only when its meaning and parameters match. Keep related keys together and update both JSON files in the same change.

Use named placeholders such as `{path}` or `{count}`. The placeholder sets must match in every locale, though their order can differ. Positional fields, attribute/index access, formatting specifications and conversions are rejected. Use UTF-8; the generator rejects duplicate keys and illegal control characters. Translate complete phrases rather than joining grammar-dependent fragments. Preserve literal commands and IDs inside sentences.

```python
from claude_statusline.i18n import message, translate

notice = message("cli.language_saved", language="简体中文")
print(notice.render("zh-CN"))
heading = translate("settings.ui-language", "en")
```

`Message` remains an English-compatible string for diagnostics and existing machine interfaces. Present it in an explicit language at the interface boundary. Its wire form is `{key, params, fallback}`; nested messages retain metadata. TypeScript `text` creates that wire form, and `renderMessage` presents it. Business logic must use stable error codes or keys. External-program errors stay raw details. Avoid global locale state or process-wide argparse patches.

## Scope and persistence

Translate the tool's own menus, catalog names/descriptions, forms, choices, help, progress and recovery messages. The language selector always shows **English / 简体中文**. Preserve commands, IDs, persisted values, JSON catalogs, model names, paths, branches, custom labels/input and hotkeys. Interface language does not change statusline content; the independent display language controls production/sample content. Preview captions use the interface language.

`config/ui_preferences.py` owns `statusline-ui.json` (schema v1) under the resolved Claude config directory. Reads are side-effect-free and return English plus an optional warning for invalid data. Explicit writes reuse the storage lock, backup and atomic write; newer schemas are protected. A language change is an immediate independent effect, outside display drafts, revisions, presets, imports and exports. Apply a new interface language only after a successful write. Keep the current page, selection, search and input and recompute cell budgets. Curses invalidates its physical screen to repaint wide-character runs.

Configuration protocol v7 exposes `read_ui_preferences` and `set_ui_language`; display schema v6 and runtime protocol v2 evolve independently. The `describe` catalog stays English. Both editors search stable IDs, English/Chinese labels and descriptions, and custom labels. Existing open windows reread language on reopen/reload; there is no background preference polling.

## Ranked catalog search

Both editors search each ID, English/Chinese name and description, custom label,
and category code/name independently. The best field match wins: exact, prefix,
English word initials, substring, then ordered subsequence. Equal ranks retain
the full editor order, including when a category name gives several items the
same rank. Search uses per-code-point NFKD normalization and lowercase, with
trimmed/collapsed Unicode whitespace; positions map back to original code points.
No process locale or backend request participates in a keystroke. A changed
query focuses a better-ranked result; later navigation can select weaker ones.

`/` edits a query, including literal spaces; Enter accepts and Ctrl+G cancels.
Curses also retains direct typing, and Esc cancels its explicit search input.
Ctrl+F opens an ephemeral category picker. Both category and query filtering
disable reordering, but selection and formatting remain available. Clearing the
query and selecting All restores the full order. Matching text is emphasized
with the terminal's existing styles; an alternate-field hit shows its original
text near the match instead of highlighting unrelated translated text.

`tools/generate_editor_fixtures.py` generates native test fixtures from the
canonical catalog and shared JSON cases. Run its `--check` mode with the existing
generation checks. Fixtures are included in source distributions, not wheels.

## Validate a change

```bash
python tools/generate_i18n.py
python tools/generate_i18n.py --check
python tools/generate_ui_contracts.py --check
python -m unittest tests.i18n.test_translation tests.ui.test_language tests.integration.test_language_cli
python tools/check_docs.py
```

Prepare exact-host Mod declarations, type-check both Mods and run `claude plugin test mods/statusline-native`. Complete workflow tests have a bounded 20-second timeout for slower platform runners; assertions remain active. CI checks generated resource synchronization and packaged JSON/TypeScript bytes.

Exercise both directions, read-only corrupt fallback, future schema refusal, failed/concurrent writes, directory isolation, CLI override and help/errors. Verify draft/save/cancel, input/search retention and custom labels. Check CJK, combining characters and long text at native 32×12 and external 64×18, plus normal/resize viewports, using the existing cell-width helpers.

Installed-package Linux PTY language checks use local commands and fixed samples:

```bash
python tools/external_tui_acceptance.py --language-only --backend /absolute/path/claude-statusline \
  --commit VERIFIED_SHA --report-dir dist/validation/new-external-language
python tools/native_mod_acceptance.py --persistent --language-only --theme light --terminal-theme light \
  --backend /absolute/path/claude-statusline --report-dir dist/validation/new-native-language
```

Keep raw output private and ignored. Inspect decoded cells and reconstructed PNGs; record the source commit, installed package, platform, host, viewport, palette and capture method. A multiplexer may quantize RGB to 256 colors; record that scope separately from direct RGB captures. Automated tests and agent image inspection do not establish new human or Windows/macOS terminal acceptance. See [testing](testing.md) and [release gates](../RELEASING.md).

## Statusline presentation

`statusline.*` messages in the same canonical JSON packs generate `i18n/_generated_statusline.py`; `i18n.statusline` loads only that small Python dictionary. Normal rendering does not read UI preferences or parse UI JSON. Pass the display language explicitly through production and preview formatters; localize known enum values only at presentation boundaries. Keep raw observations, technical units and user text intact. Item-scoped prefix metadata identifies owned labels for decoration; never match arbitrary payload text against English words. English legacy output stays compatible.

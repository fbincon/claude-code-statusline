# Interface translation and contributions

**English** | [简体中文](i18n.zh-CN.md)

The CLI, both editors, previews and production statuslines share semantic messages. English is the source and fallback language. Complete documentation is maintained in English and Simplified Chinese; adding an interface language does not require another copy of every document.

## Resource ownership

```text
packages/core/resources/i18n/
  languages.json             Canonical ordered codes and native names
  locales/<code>.json        Canonical UTF-8 message packs
packages/core/src/i18n/       Shared TS messages and generated per-language output
archive/python/src/claude_statusline/i18n/   Frozen Python reference; never regenerated
mods/statusline-native/lib/i18n/
  generated-locales.ts        Generated registry, types and messages; never edit
  index.ts                   Generated copy of the shared pure translator
tools/generation/resources.ts TypeScript resource writer and drift/coverage checks
tools/migration/ts-05/reference.ts Independent historical comparison entry
```

Supported codes, in selector order, are `en`, `zh-CN`, `zh-Hant`, `ja`, `ko`. Their autonyms are English, 简体中文, 繁體中文, 日本語, 한국어. `zh-Hant` uses general Traditional Chinese terminology, without a Taiwan/Hong Kong regional variant. Codes are explicit and case-sensitive; aliases and system-locale detection are not supported.

To add a language, append its code/name to `languages.json`, add `locales/<code>.json`, then run the generators below. The registry must match the discovered packs exactly, with English first. New languages require no changes to selectors, CLI choices, protocol enums, search, or installed wizard language lists. Generated files are committed and checked in CI; runtime code never discovers languages by scanning directories.

Every registered pack must contain exactly the English message keys. `--coverage` reports missing keys without writing; `--check` and generation reject incomplete packs, extra/duplicate keys, empty translations of nonempty messages, unsafe text and mismatched placeholders. Coverage is key completeness, not evidence of native-speaker review. Runtime lookup retains English fallback for missing keys and internal unknown-language requests; explicit configuration writes reject unsupported languages.

Use semantic keys and named placeholders such as `{path}` or `{count}`. All languages must preserve the placeholder set; their order may differ. Positional fields, attribute/index access, formatting specifications and conversions are rejected. Statusline strings must be single-line terminal-safe text, and labels/enum values cannot contain placeholders. Translate complete phrases; preserve commands, IDs, user text and technical units. Do not add runtime translation-service dependencies.


Use the pinned Node 24.21.0 toolchain for generation. Edit only the canonical resource directory above; core and Mod copies are generated together. TS-05 freezes the Python archive and excludes it from generation. Historical comparisons reconstruct the original source layout.

## Scope and persistence

Interface language covers menus, catalog descriptions, forms, choices, help, progress and recovery messages. `Message` remains an English-compatible diagnostic string with a `{key, params, fallback}` wire representation; present it in an explicit language at the UI boundary, including nested errors. Keep business decisions on stable codes rather than translated strings. External errors remain raw details.

`statusline-ui.json` remains schema v1. Reads are side-effect-free; corrupt preferences return English and a warning. Explicit writes use locks, backups and atomic replacement; newer schemas remain protected. Switching interface language saves immediately, preserves page/selection/search/input/draft and repaints cell budgets. Failed writes retain the prior language. Other windows read preferences on reopen/reload, without background polling.

Output language is independent, defaults to English and is stored in display schema v8. Its preview changes with the draft; normal Save/Cancel controls persistence. Editor protocol v11 derives both language types and accepted values from the registry and rejects older frontends. Portable v1 and runtime v2 remain independent. Before downgrading to a package without a selected language, reset both language settings to English and reinstall matching native resources.

## Ranked catalog search

Both editors prepare labels, descriptions and category names for all registered languages, plus IDs and custom labels. Prepared fields retain normalized text and original code-point positions. Queries perform no translation/resource reads; editing a custom label refreshes its own cached field. Interface switches reuse the same multilingual index.

Ranking remains exact, prefix, English word initials, substring, then ordered subsequence, with stable original-order ties. Both implementations apply per-code-point NFKD and lowercase plus collapsed Unicode whitespace. Shared fixtures include Traditional Chinese, kana width/combining marks and Hangul. Matching text is highlighted; alternate-language hits show their original evidence. Category/query filters retain existing reorder protection, selection and draft behavior.

## Validate a change

```bash
npm ci --ignore-scripts --no-audit --no-fund
npm run generate
npm run languages:coverage
npm run generate:check
npm run check
npm run docs:check
```

Prepare exact-host declarations, type-check both Mods and run their official tests. Check all 25 interface/output language combinations, forward/backward cycling, save/cancel/reopen, failed writes, import/export and upgrade preservation. Check native 32×12 and external 64×18 minimums plus common/resize viewports, long text, Unicode and both background themes. Inspect installed-wheel PTY captures and record package/source/host/viewport provenance; CI and agent inspection are distinct from human or Windows/macOS terminal acceptance. Follow [testing](testing.md) and the [release gates](../RELEASING.md).

## Statusline presentation

Only `statusline.*` messages are generated into individual TypeScript language modules. Rendering imports the selected module on first use; English is loaded only when needed for fallback. It never parses interface JSON or reads interface preferences. Interface catalog caches cover the registered languages and normalize unknown internal requests before caching.

Pass output language explicitly through production and preview formatters. Translate known enum values at presentation boundaries and keep raw observations, numbers, units, IDs and user labels intact. Owned prefix metadata drives decoration; never recognize labels by matching arbitrary payload text. Keep existing English statusline bytes compatible. Benchmark fixed-source cold/warm startup, rendering and search; separate resource-volume effects from steady refresh costs.

# D01 — 运行时、分发与布局

[English](D01.md) | **简体中文**

状态: **OPEN**. 日期: 2026-10-12 (Asia/Shanghai).

证据和阶段状态见 [TS-02](README.zh-CN.md)。

## 方向

固定候选及最低实测版本为 Node 24.21.0；本机包管理器为 npm 11.19.0，TypeScript 5.9.3 编译 ESM，由 Node 内置测试器运行探针。探针包为 private、版本 0.0.0，与生产应用分离。

## 接口与行为

目标为 Linux x64／WSL Linux、Windows x64（包括 ARM 上的 x64 仿真）及 macOS 14+ Intel／Apple Silicon。维护者已批准未来 TS 主版本退役 Windows x86；保留旧 Python 发布物，不新增维护承诺。不自动新增 Windows 原生 ARM 或其他 Linux 架构。未来安装指南须明确 Node 的系统与 libc 要求。

[Node 24 官方平台表](https://github.com/nodejs/node/blob/v24.x/BUILDING.md#platform-list)中，Tier 1 Linux x64 要求内核 4.18+／glibc 2.28+，Windows x64 从 Windows 10／Server 2016 起，macOS 从 13.5 起；同时排除系统厂商已结束支持的版本。本产品 macOS 下限仍为 14，runner 通过不会扩大上游边界。官方归档校验值见 [runtime-lock.json](../../../../tools/migration/ts-02/runtime-lock.json)。

## 验证

未来采用私有 npm workspace，将核心、平台适配、CLI、外部 TUI 分为 packages/core、packages/platform、packages/cli、packages/tui。既有 Mod 独立验证，共享纯模块打包到宿主支持的模块根目录；平台适配和编辑器资源不得进入渲染器的急切导入路径。TS-02 只记录布局，不建立生产骨架。

## 替代方案与限制

Node 22 可延续 x86 支持，但支持周期更短；Bun 和 SEA 会增加运行时或资源／原生扩展打包门槛。本次 npm 优先分发不要求它们。Koffi 3.3.3 与 lossless-json 4.3.1 为 MIT；复用 Unicode 资源保留仓库的 Unicode 许可。

## 恢复及出口

必需的原生／安装自动矩阵和未覆盖目标的明确处置齐备后才能关闭。runner 标签不能证明 Windows 10 桌面、WSL 或 macOS 14 Intel 支持。保留 Python 安装作为回退；TS-02 不修改用户安装。

2026-10-12 的[本机补验](README.zh-CN.md#2026-10-12-本机-windows-补验)已覆盖 Windows 11 x64
及其 WSL2 Ubuntu 24.04.4 x64 的原生／安装自动检查。WSL 的 PTY 和 tmux session 通过，
但不据此扩大为 GUI／popup、其他 WSL 发行版、Windows 10 或 macOS 14 Intel 的支持证明。

## 复现与恢复

使用 Python 3.14.4 和锁定 Node 的绝对路径运行[电源取证工具](../../../../archive/python/tools/linux_clock_smoke.py)。
每次动作使用新输出目录；`before` 不会触发睡眠或重启：

```bash
.venv/bin/python tools/linux_clock_smoke.py before --kind suspend --node /absolute/locked/node --output /absolute/new-power-record
# 完成约定的真实 OS 动作后：
.venv/bin/python tools/linux_clock_smoke.py after --output /absolute/new-power-record --action-confirmed
```

重启另建记录并使用 `--kind reboot`。`after` 拒绝源码变化或覆盖已有结果。
运行 `tools/ts02_linux_terminal_smoke.py launch --node /absolute/locked/node --output /absolute/new-terminal-record --mode direct`，
再使用新目录运行 `--mode popup`；按键和视觉确认均由操作者完成，未回答不算通过。
这些工具使用隔离目录，不替换已安装后端或用户配置。

原生／安装检查使用 [TS-02 命令](README.zh-CN.md#复现)。由 [PR #77](https://github.com/fbincon/claude-code-statusline/pull/77) 跟踪。CI／合并检查必须核对最终 PR head，早期本地记录保持原始哈希。
本轮未声称重跑 Linux 性能：原 Linux 和导入 macOS 的最小 profile 测量继续限于各自源码与冻结预算。

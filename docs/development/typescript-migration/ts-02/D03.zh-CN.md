# D03 — 兼容文件锁与持久化

[English](D03.md) | **简体中文**

状态: **DECIDED**. 日期: 2026-10-12 (Asia/Shanghai).

证据和阶段状态见 [TS-02](README.zh-CN.md)。

## 方向

优先保留既有锁命名空间：POSIX 使用 flock，Windows 使用 LockFileEx 锁定首字节，包括空锁文件；关闭 Windows 原生句柄释放锁。各原生目标须通过 Python／TS 独立写入者、双向持有／等待及终止持有者的测试。

## 接口与行为

通过同目录私有临时文件写入、刷盘、原子替换，并在 POSIX 同步父目录。仅 macOS 既有“不支持目录同步”错误可降级。Windows 按固定的 10／20／40／80／160 ms 间隔重试共享／访问冲突；永久失败保留原目标。

## 验证

测试覆盖 16 个混合竞争写入者、Python／TS 双向终止释放、注入发布失败、替换前后终止、POSIX 权限、符号链接／reparse point 及真实 Windows 共享拒绝。崩溃测试只接受完整旧值或新值；强制终止可能留下私有临时文件，测试器只清理自身隔离运行的文件。

## 替代方案与限制

拒绝静默改成 mkdir 锁，因为旧 Python 写入者不参与该锁。备份／恢复须处于同一存储锁内。本验证不构成 NFS／SMB、断电或竞态安全沙箱保证；完整生产事务和遗留临时文件所有权／恢复策略仍属 TS-03／TS-04。

## 恢复及出口

`f891065` 的八目标原生矩阵通过，包括 Windows 与 Python 的双向互斥，因此原语及策略已定案。完整生产存储事务及安装升级验收仍在 TS-03／TS-04；这不启用真实 TS 写入者。后续目标验证若推翻锁互操作结论，重新打开 D03 并隔离写入者。

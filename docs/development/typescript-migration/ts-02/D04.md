# D04 — External terminal and launching

**English** | [简体中文](D04.zh-CN.md)

State: **OPEN**. Date: 2026-10-12 (Asia/Shanghai).

Evidence and stage status:  [TS-02](README.md)。

## Direction

Candidate: Node raw TTY input plus bounded VT output and the existing Unicode 18.0 grapheme/cell kernel. Avoid choosing a replacement widget framework before the input, restoration and launcher boundaries work.

## Interface and behavior

POSIX native PTYs exercise Ctrl+S, Ctrl+C, arrows, Chinese/combining/emoji input, resize, SIGTERM and full terminal-attribute restoration at five working sizes and 32×12 guidance. tmux starts the actual helper and returns a nonce-bound result. A Windows CREATE_NEW_CONSOLE probe opens genuine console input/output handles and toggles/restores raw mode.

## Validation

Launcher requests bind a nonce, expiry and parent process-start identity. Tests reject wrong/replayed/expired requests and PID-token reuse. GNOME argv and macOS .command generation preserve quoting and Unicode paths. Generated launch commands do not count as actual GUI execution.

## Alternatives and limitations

Keep D04 OPEN: Windows keyboard/resize/restoration through a real interactive console, GNOME/Terminal.app GUI handshake and focus, tmux popup behavior, and human visuals remain required. Windows skips of POSIX PTYs are explicit, not passed cases. SIGKILL cannot run terminal cleanup; do not promise it can.

## Recovery and exit

Complete these platform checks before treating the external terminal design as proven. Full four-page editing, Apply/Save behavior and integration recovery remain TS-04. Existing macOS Client input limitations remain documented.

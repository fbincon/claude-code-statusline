# D05 — Entry retirement, installation and recovery

**English** | [简体中文](D05.zh-CN.md)

State: **OPEN**. Date: 2026-10-12 (Asia/Shanghai).

Evidence and stage status:  [TS-02](README.md)。

## Direction

The maintainer approved npm-first delivery in a future major release, preserving CLI capabilities while retiring Python imports, python -m, pipx installation and the old .exe name. Historical Python packages remain the rollback/32-bit path; TS-02 does not uninstall or modify them.

## Interface and behavior

Use LaunchSpec { executable, args } internally. Bind the absolute Node executable and installed JS entry; a legacy single executable maps to empty args. Existing executable environment overrides replace the whole binding, so old overrides never receive the new JS prefix accidentally. Probe backendArgs as a string array (host manifest type:string, multiple:true).

## Validation

Install a packed tarball outside the checkout with lifecycle scripts disabled and PATH excluding Python/compiler directories, then load the native dependency, read packaged fixtures and compare render bytes. Exercise the POSIX npm bin, PowerShell .cmd and Git Bash npm shim. On PowerShell, a .cmd invocation avoids changing script execution policy.

## Alternatives and limitations

Temporary copies of both Mods add the argv prefix and call the Node receipt backend through the real host process API. The free local host smoke uses a synthetic key and unreachable loopback API, sends only a local slash command and proves invocation, not backend protocol/UI parity. Production Mod sources and protocol versions remain unchanged.

## Recovery and exit

Upgrade strategy: detect pipx/PATH collisions; validate ownership; preserve an immutable compatible backup; rebind only owned settings/resources under a lock; retain unrelated settings and explicit opt-outs; restore the original bytes on failure. Keep the old Python environment available until the new installation is validated. Full install/doctor/uninstall and interrupted multi-file recovery are TS-04 gates; the isolated fixture transaction is only a prototype.

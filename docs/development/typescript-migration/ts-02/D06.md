## Applicability amendment, 2026-10-15

The maintainer approved completing the whole TypeScript migration before further
performance optimization. Full D06 measurement and a passing D06 result are no
longer prerequisites for TS-03–TS-06, including preview and stable delivery.
Performance work belongs to the independent [PERF-01](../../performance/perf-01.md)
after TS-06; that work is NOT_STARTED and is not started by this documentation change.

This amendment supersedes the original migration/TS-05 performance gate below,
not the numerical policy, measurement method or repeat restrictions. The latest
TS-03 measurement remains **FAIL: 104 pass / 60 fail / 28 inconclusive**. Preserve
the frozen policy, oracle, fixtures and every historical result. Under the revised
non-performance criteria, TS-03/03-F are DONE on existing functional and CI evidence;
TS-04–TS-06 remain NOT_STARTED.

Functional and stability failures, timeout contracts, bounded resources, lost
events, save failures, locking and data integrity still require validation.
Physical/desktop and installation/recovery release gates remain unchanged.
TS-06 records the final source/artifact identity and known performance limitations;
PERF-01 performs the full final-product comparison after migration completion.

## Direction

Freeze the maintainer-approved policy before candidate measurements. Commit 3c448b8 records policy.json before the first probe implementation. Originally a migration acceptance rule, the budget now remains a PERF-01 target; it does not promise that TypeScript is faster or smaller.

## Interface and behavior

For each matched case with Python metric B: command P50 ≤ B + max(0.10B, 5 ms), command P95 ≤ B + max(0.15B, 10 ms); in-process floors are 0.1/0.2 ms with the same ratios. Peak process RSS ≤ B + 32 MiB. Preserve the 100/10,000/100,000 transcript, 0/8/32 Agent and 32/1,000/10,000 Git-file profiles for the future full candidate.

## Validation

Same machine, fixed source/harness/fixtures, 50 samples per side per round, three alternating rounds, separate cold/warm Python bytecode. Setup and priming are outside measurements. Both renderers start in fresh processes; stdout must match the frozen case. RSS comes from process peak resident/working-set counters, not V8 heap size. Runtime startup/native loading controls are separate descriptive measurements.

## Alternatives and limitations

Fail when all three rounds exceed budget and the median increase exceeds the baseline between-round range. A mixed/noisy excess is inconclusive, not pass; permit at most one additional complete three-round set and retain both. No post-result budget relaxation. An intentional harness change requires new provenance and an explicitly separated measurement, not replacing raw results.

## Recovery and exit

At the original decision, TS-02 measured only the real minimal model render profile; other command, collector, Agent and in-process cases awaited equivalent candidates. Complete TS-03 measurements now exist and remain failed. Keep near-limit RSS visible in summaries. The original requirement to run the complete matrix before TS-05 release acceptance is superseded by the amendment above; final-product measurement belongs to PERF-01 after TS-06.

For an inconclusive result only, invoke `benchmark -- NEW_DIRECTORY --repeat-of REPORT.json`. The parent report must match the measured graph and policy, contain no failed metric, and have no previous repeat. An exclusive reservation beside the canonical parent path prevents reusing the same parent for another attempt. Keep the reservation and both reports.

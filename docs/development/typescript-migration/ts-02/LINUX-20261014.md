## Reproduction and recovery

Run [the power collector](../../../../tools/linux_clock_smoke.py) with Python
3.14.4 and an absolute locked Node path. Use a new output directory for each
action; `before` never initiates sleep/reboot:

```bash
.venv/bin/python tools/linux_clock_smoke.py before --kind suspend --node /absolute/locked/node --output /absolute/new-power-record
# Perform the agreed real OS action, then:
.venv/bin/python tools/linux_clock_smoke.py after --output /absolute/new-power-record --action-confirmed
```

Use `--kind reboot` for a separate reboot record. `after` refuses changed source
bytes or overwriting a previous result. Run
`tools/ts02_linux_terminal_smoke.py launch --node /absolute/locked/node --output /absolute/new-terminal-record --mode direct`
and then a new directory with `--mode popup`; all input and visual confirmations
come from the operator. Unanswered confirmation is not a pass. These tools use
isolated directories and never replace the installed backend or user settings.

Follow the [TS-02 commands](README.md#reproduce) for native/installation checks.
The CI/merge gate must use the final PR head; earlier local measurements keep
their original hashes. No new Linux performance run is claimed: the minimal
profile measurements in the original Linux and imported macOS records remain
scoped to their original sources and frozen budgets.

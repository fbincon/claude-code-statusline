# 界面翻译与贡献

[English](i18n.md) | **简体中文**

CLI、两种编辑器、预览与实际状态栏共用语义消息，英文为基准和回退语言。完整文档维护英文、简体中文两套；增加界面语言不要求复制全部文档。

本指南描述 I18N-02 [增量工作流](i18n-workflow.zh-CN.md)。开发期间英中保持完整；公开发布前十二个官方语言必须全部验收。参见[实现与证据](i18n-02-delivery.zh-CN.md)。

## 资源归属

```text
packages/core/resources/i18n/
  languages.json             规范语言代码顺序与语言自称
  locales/<code>.json        规范 UTF-8 消息资源
packages/core/src/i18n/       共享 TS 消息与按语言生成的输出模块
archive/python/src/claude_statusline/i18n/   冻结的 Python 参考，不再生成
mods/statusline-native/lib/i18n/
  generated-locales.ts        生成的注册表、类型和消息；禁止手改
  index.ts                   共享纯翻译器的生成副本
tools/generation/resources.ts TypeScript 生成、漂移检查及覆盖率
tools/migration/ts-05/reference.ts 独立历史对照入口
```

支持顺序为 `en`、`zh-CN`、`zh-TW`、`zh-HK`、`ja`、`ko`、`es`、`fr`、`de`、`pt-BR`、`ru`、`id`，原生名称依次为 English、简体中文、繁體中文（台灣）、繁體中文（香港）、日本語、한국어、Español、Français、Deutsch、Português (Brasil)、Русский、Bahasa Indonesia。台湾和香港维护完整独立资源。语言显式指定并区分大小写；兼容别名 `zh-Hant` 在 CLI、界面偏好、显示配置和导入边界映射到 `zh-TW`，不作为额外选项。读取仅在内存规范化，显式保存与导出使用规范代码；不支持其他别名或系统语言自动识别。

未来新增语言须明确维护范围、构建期策略中的支持级别、验收文件及对应界面／输出／搜索／布局检查。在 `languages.json` 追加代码和原生名称，添加真实 `locales/<code>.json`，验证元数据后再生成。[语言扩展](language-expansion.zh-CN.md)新增六种完整 B 类语言。注册表必须与发现的资源包完全对应，英文排在第一位。选择器、CLI 选项、协议语言枚举、搜索与安装后向导的语言列表均从注册表派生，不另行维护列表。扩展允许的语言值时须检查前后端兼容性。生成文件提交入库并由 CI 校验，运行时不扫描目录发现语言。

原始语言包只存真实译文。`en`／`zh-CN`（A）在开发期间须完整且已验收；其他全部注册语言（B）的缺失、陈旧或待验证条目可使用当前英文。公开发布要求 A/B 全部验收。不合法类型、重复键、不安全文字、新提交的占位符错误及无法解释的额外键均失败。仅未改动且具有可验证旧验收／契约的条目可隔离为历史；退休键不进入有效资源或覆盖率分母。报告区分原始存在、当前有效、已验收和英文回退，均不代表母语审阅。显式配置写入仍拒绝不支持的语言。

使用语义键和 `{path}`、`{count}` 等命名占位符。所有语言的占位符集合必须一致，但顺序可以改变。禁止位置参数、属性／索引访问、格式说明和转换。状态栏消息必须是单行终端安全文本，标签与枚举值不得包含占位符。翻译完整短语，保留命令、ID、用户文本和技术单位，不引入运行时翻译服务依赖。


使用固定的 Node 24.21.0 工具链生成资源。编辑规范原始消息及构建期生命周期输入，core 与 Mod 有效副本统一生成；验收记录使用下方显式命令更新。TS-05 冻结 Python 归档，不再生成其中的副本；历史对照重建原始源码布局。

## 注册表变更与引导生成

新增、删除或重排语言代码前，先构建当前检出，准备编译后的生成器：

```bash
npm run build
```

然后修改规范注册表、真实语言包及对应的生命周期策略／验收输入。使用已构建的生成器引导生成语言资源，再执行常规生成和检查：

```bash
node dist/typescript/tools/generation/resources.js --languages-only
npm run generate
npm run generate:check
```

`--languages-only` 使用当前有效语言分析，写入生成的语言注册表、字典、状态栏模块及按语言划分的宿主测试入口，并移除已废弃且归生成器所有的语言文件。契约、容量夹具和其他资源不属于此引导模式。追加 `--check` 可只读检查语言生成文件。

常规生成先将更新后的注册表构建到 core，再构造容量草稿。容量生成要求规范与已编译的语言代码列表一致；不一致时失败并给出引导生成／重建指引，不跳过语言或放宽草稿校验。引导生成是中间步骤，不代表完整生成或验收。仅修改译文不需要此步骤：常规生成在一遍执行中，将同一份当前有效消息提供给语言输出与容量预览，包括待验收条目的英文回退。

## 增量维护

`tools/generation/i18n/data/` 中的构建期输入包含 `policy.json`、`context.json`、`terminology.json`、按语言划分的 `accepted/` 记录、`history.json`、`provenance.json` 和已验证基线快照。它们进入可复现源码归档，不进入 npm 运行包。包内 JSON、Node 界面字典、Native 分语言模块及状态栏模块均使用同一份有效分析结果。

签名绑定准确英文、命名占位符、语义上下文及引用的术语。英文未变但含义变化时须修改上下文含义／版本；术语变化仅使引用它的键失效。译文修改使旧哈希验收失效，不为凑存在率而向原始包填入英文。命令和技术术语经过验证后可以合法地与英文相同。

```bash
npm run languages:coverage
npm run languages -- report --format text
npm run languages -- freeze --commit FULL_HEAD_SHA --base FULL_BASE_SHA --output dist/validation/language-freeze.json
npm run languages -- validate --language ja --keys settings.ui-language --review 'Reviewed the immediate-save meaning and terminology in context.' --output dist/validation/language-validation.json
npm run languages -- accept --validation dist/validation/language-validation.json --output dist/validation/language-accepted.json
npm run generate
npm run generate:check
npm run languages -- release-check --format text
```

使用新的报告路径。`freeze` 读取不可变 Git 输入，不联网、不构建或运行测试；列出新增、改义、改占位符、删除和未完成条目，附英中参考、占位符、上下文、术语及已声明的单元格预算。`report`、`freeze`、`validate`、`release-check` 不修改源或验收。`accept` 先核对准确当前输入身份，再显式更新记录／历史；源或策略变动后需要重新验证。上下文审阅文字记录实际完成的工作，不引入新的审阅者批准。结构检查不代表语言质量，还须执行影响计划选中的产品／布局检查。

生成／检查要求 A 完整且所有语言安全。发布检查要求 A/B 全部完成，也适用于预览版；未来获准的 C 语言须明确披露验收与回退。就绪 PR／main 产品验收可保留安全 B 回退，但不因此获得发布资格。完整来源和维护来源的发布分别验证匹配的语言证据；报告不能将缺失或过期 CI 证据变成通过。

## 范围与持久化

界面语言覆盖菜单、目录说明、表单、选项、帮助、进度和恢复消息。`LocalizedText` 携带 `{key, params, fallback}` 及兼容英文的诊断回退，在 UI 边界按明确语言展示，嵌套错误也保留元数据。业务判断使用稳定代码，不依赖翻译文本；外部错误细节保持原文。

`statusline-ui.json` 继续使用 schema v1。读取无副作用，损坏偏好返回英文及警告；显式写入使用锁、备份及原子替换，并保护未来 schema。界面语言切换立即保存，保留页面、选中项、搜索、输入和草稿，重新绘制字符单元格。写入失败保留原语言。其他窗口在重开／重新加载时读取偏好，不后台轮询。

输出语言独立、默认英文，保存在显示配置中。预览跟随草稿变化，正常 Save／Cancel 控制持久化。v3.16.0 保留显示 schema 17，扩展语言值采用编辑器协议 31；两种语言类型与允许值从注册表派生，协议校验拒绝不匹配的前端。Portable v1、runtime v3 与 UI preferences v1 保持独立，参见[共享契约](contracts.zh-CN.md)。Claude 偏好仍独立 Apply。降级到不支持所选语言的版本前，将两种语言重置为英文并重新安装匹配的原生资源。

## 项目分级搜索

两个编辑器预建所有注册语言的名称、说明和分类索引，加上 ID 与自定义标签。字段保存规范化文本和原始码点位置；查询时不重新翻译或读取语言资源，修改自定义标签仅刷新对应缓存字段。界面切换继续使用同一份多语言索引。

排名保持精确、前缀、英文单词首字母缩写、连续子串、有序子序列，同级保持原顺序。两端按码点执行 NFKD、小写及 Unicode 空白折叠。共享测试包含繁体中文、假名宽度／组合标记及韩文。高亮真实匹配文字，跨语言命中显示原始证据。生成的回退列表将英文证据归为英文；合法且已验收的同英文技术术语保留所属语言。分类／查询筛选保留既有排序保护、选择和草稿行为。

## 校验修改

按[开发指南](README.zh-CN.md#开发与测试)使用固定工具链准备依赖。修改规范语言资源后，重新生成并核对所属副本：

```bash
npm run generate
npm run languages:coverage
npm run generate:check
```

纯文档变更只需：

```bash
npm run docs:check
git diff --check
```

已提交的翻译维护使用不可变 base／head 执行 `npm run ci:plan` 及其选定的 `npm run ci:check` 任务，需要包比较时先解决比较；遵循[影响检查](impact-checks.zh-CN.md#本地接口)。既有译文值在键／占位符不变、生成副本和实际归属一致时，才适用 presentation 检查。语言注册、键／占位符、默认值或产品行为变化要求产品路线及本地 `npm run check`。混合变更取检查并集，未知归属或比较未解决继续阻断，不因改了翻译文件就运行完整矩阵。

保留 144 种界面／输出组合、正反切换、保存／取消／重开、失败写入、导入导出及升级覆盖。对受影响的原生 32×12、外部 64×18 最小视口，常见／缩放视口、长文案、Unicode 和浅深背景扩展既有案例。适用 Native 宿主检查保留 props、Pane、Client 树的独立预算及恢复，遵循[容量规则](native-capacity.zh-CN.md)。对计划选中的受影响 Mod 执行官方验证／测试及可用的精确宿主声明检查，继续明确记录现有 2.1.296 声明缺口。

需要安装版终端证据时，采集已安装的 TypeScript npm 候选，记录包、源提交、宿主和视口。自动测试、实际宿主挂载、PTY、代理观察与 Windows／macOS 实体终端验收含义不同。遵循[测试说明](testing.zh-CN.md)和[发布门槛](../RELEASING.zh-CN.md)，保留已验证的 [PR／main／tag 复用](ci-maintenance.zh-CN.md#候选包在-prmain-与-tag-之间晋级)。这些是逻辑覆盖义务，不要求每种语言或每次提升重复全部流程。[Issue #96 六项已接受缺口](https://github.com/fbincon/claude-code-statusline/issues/96)继续未验证，不豁免新增失败。

## 状态栏展示

只有 `statusline.*` 消息生成到独立 TypeScript 语言模块。渲染首次使用时加载所选完整有效模块，开发回退已在生成时由当前英文物化；不解析界面 JSON，也不读取界面偏好。界面缓存覆盖注册语言，内部未知语言在进入缓存前归一到英文。

生产与预览格式化明确传递输出语言，在展示边界翻译已知枚举，保留原始观测、数字、单位、ID 与用户标签。修饰使用所属前缀元数据，不以任意文本识别标签；保留现有英文状态栏输出字节。

## 地区用词

公开发行版中两套繁体资源均覆盖全部英文键，保持占位符、命令、ID、数字和技术单位。台湾采用「介面、設定、儲存、檔案、資料夾、軟體、使用者、資料、網路、狀態列」；香港采用正式书面中文及「介面、設定、儲存、檔案、資料夾、軟件、用戶、數據、網絡、狀態欄」。现有「記憶體、快取、欄位、字串、字元」统一使用。完整率检查不代表母语审阅；当前接口以上方持久化章节为准，语言值及兼容别名使用共享规范化规则。

Native 界面翻译在 `mods/statusline-native/lib/i18n/locales` 按语言生成独立模块，并由小型生成注册表汇总。每个导入模块须低于官方宿主限制（当前验收为 1 MiB），生成测试检查该边界，不减少消息或语言。Node 界面缓存仍合并。

## 新增语言约定

西班牙语（`es`）、法语（`fr`）和德语（`de`）采用通用技术表达；葡萄牙语（`pt-BR`）采用巴西术语。俄语（`ru`）和印度尼西亚语（`id`）采用本语言文字及常用技术术语。代码必须准确匹配：`pt`、`pt-br` 和其他地区变体不是别名。结合上下文翻译操作、恢复结果及剩余／已用百分比，保留命令、单位与用户内容。新增语言记录代理上下文复核和结构／布局验收，不推断为母语审阅。

Node 聚合字典显式标注语言和消息键类型，使声明大小按键注册表增长，避免重复展开全部译文的字面量类型。Native 仍使用按语言分割的模块与有界可见帧。

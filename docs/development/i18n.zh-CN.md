# 界面翻译与贡献

[English](i18n.md) | **简体中文**

英文和简体中文界面共用一套语义消息。Python 管理源语言包，TypeScript 使用生成数据。修改翻译时遵循[开发检查](README.zh-CN.md#运行检查)及[用户语言行为](../USER_GUIDE.zh-CN.md#界面语言)。

## 资源归属

```text
src/claude_statusline/
  config/ui_preferences.py          共享偏好存储与事务
  i18n/
    locales/en.json                英文基准消息键
    locales/zh-CN.json             对应简体中文翻译
    translator.py                  延迟消息、参数与回退
    argparse.py                    各解析器的帮助及错误展示
    presentation.py                字段、选项与双语搜索
mods/statusline-native/lib/i18n/
  generated-locales.ts             自动生成，禁止手改
  index.ts                        显式语言翻译及消息校验
  messages.ts                     跨冻结 Client 端口的语义消息
  presentation.ts                 标签、选项与快捷键展示
tools/generate_i18n.py             校验与确定性生成
tests/i18n/                       资源及回退测试
tests/ui/test_language.py          外部编辑器语言行为
tests/integration/test_language_cli.py
mods/statusline-native/tests/integration/language.test.ts
```

支持 `en`、`zh-CN`，英文为回退语言。每种语言必须与英文包含完全相同的键。键表达含义，应在修改文案时保持稳定；仅在含义和参数一致时复用。相关键放在一起，两套 JSON 在同一修改中更新。

使用 `{path}`、`{count}` 等命名占位符。各语言占位符集合必须一致，顺序可以不同。拒绝位置参数、属性／索引访问、格式规格和转换。文件使用 UTF-8；生成器拒绝重复键及非法控制字符。翻译完整句子，避免拼接依赖语法的片段。句子内的命令和 ID 保持字面值。

```python
from claude_statusline.i18n import message, translate

notice = message("cli.language_saved", language="简体中文")
print(notice.render("zh-CN"))
heading = translate("settings.ui-language", "en")
```

`Message` 保持英文字符串兼容性，用于诊断和已有机器接口，在展示边界按显式语言渲染。其传输格式为 `{key, params, fallback}`，嵌套消息保留元数据。TypeScript 的 `text` 创建该格式，`renderMessage` 负责展示。业务判断使用稳定错误码或消息键，外部程序错误保留原始详情。避免全局语言状态及进程级 argparse 修改。

## 范围与持久化

翻译工具自身菜单、目录名称／说明、表单、选项、帮助、进度及恢复提示。语言选项始终显示 **English / 简体中文**。命令、ID、持久化值、JSON 目录、模型名称、路径、分支、自定义标签／输入和按键保持原值。界面语言不改变状态栏内容；生产输出与样例内容由独立的显示语言控制，预览标题使用界面语言。

`config/ui_preferences.py` 管理所选 Claude 配置目录下的 `statusline-ui.json`（schema v1）。读取无副作用，无效数据返回英文及可选警告。显式写入复用锁、备份和原子写入，保护未来 schema。语言切换是立即保存的独立效果，不属于显示草稿、revision、预设、导入和导出。仅在写入成功后应用新语言，保留页面、选中项、搜索和输入，重新计算单元格预算；curses 强制重绘物理屏幕中的宽字符区域。

配置协议 v6 提供 `read_ui_preferences`、`set_ui_language`，显示 schema v6 与运行协议 v2 独立演进。`describe` 目录保持英文。两端均搜索稳定 ID、中英文名称／说明及自定义标签。其他已打开窗口在重开／重新加载时重读语言，不后台轮询。

## 校验修改

```bash
python tools/generate_i18n.py
python tools/generate_i18n.py --check
python tools/generate_ui_contracts.py --check
python -m unittest tests.i18n.test_translation tests.ui.test_language tests.integration.test_language_cli
python tools/check_docs.py
```

生成匹配宿主的 Mod 声明，检查两个 Mod 的类型并运行 `claude plugin test mods/statusline-native`。完整交互测试使用有界 20 秒时限，适应较慢的平台执行器并保留全部断言。CI 检查生成资源同步及包内 JSON／TypeScript 字节。

覆盖双向切换、损坏偏好的只读回退、未来 schema 拒绝、失败／并发写入、目录隔离、CLI 临时覆盖与帮助／错误。验证草稿／保存／取消、输入／搜索保留及自定义标签。复用现有终端宽度工具，检查中文、组合字符、长文字，以及原生 32×12、外部 64×18、常用尺寸和缩放。

安装包 Linux PTY 语言检查仅使用本地命令及固定样例：

```bash
python tools/external_tui_acceptance.py --language-only --backend /absolute/path/claude-statusline \
  --commit VERIFIED_SHA --report-dir dist/validation/new-external-language
python tools/native_mod_acceptance.py --persistent --language-only --theme light --terminal-theme light \
  --backend /absolute/path/claude-statusline --report-dir dist/validation/new-native-language
```

原始输出私有保存并忽略。检查解码单元格及重建 PNG，记录源提交、安装包、平台、宿主、视口、调色板与采集方式。复用器可能将 RGB 量化为 256 色，应与直接 RGB 采集分别记录。自动测试和代理画面检查不代表新的人类或 Windows／macOS 终端验收。见[测试](testing.zh-CN.md)和[发布门槛](../RELEASING.zh-CN.md)。

## 状态栏展示

同一套 JSON 语言包中的 `statusline.*` 词条生成 `i18n/_generated_statusline.py`，`i18n.statusline` 只加载这个小型 Python 词典。正常渲染不读取 UI 偏好或解析界面 JSON。生产与预览格式化显式传递显示语言，仅在展示边界翻译已知枚举；保留原始观测、技术单位和用户文字。按项目定义的前缀元数据识别内置标签，不用英文词匹配任意数据。英文默认输出保持兼容。

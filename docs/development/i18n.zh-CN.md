# 界面翻译与贡献

[English](i18n.md) | **简体中文**

CLI、两种编辑器、预览与实际状态栏共用语义消息，英文为基准和回退语言。完整文档维护英文、简体中文两套；增加界面语言不要求复制全部文档。

## 资源归属

```text
src/claude_statusline/i18n/
  languages.json             有序语言代码和原生名称
  locales/<code>.json        UTF-8 消息源文件
  registry.py                轻量运行时注册与内部回退
  _generated_languages.py    生成的 Python 元数据，不手工编辑
  _generated_statusline/     按语言生成的 Python 模块，不手工编辑
  translator.py              界面消息缓存与命名参数
  statusline.py              轻量输出语言展示
mods/statusline-native/lib/i18n/
  generated-locales.ts        生成的注册、类型及消息，不手工编辑
  index.ts                   显式语言翻译与协议校验
tools/generate_i18n.py        校验、覆盖率与确定性生成
```

支持顺序为 `en`、`zh-CN`、`zh-Hant`、`ja`、`ko`，原生名称依次为 English、简体中文、繁體中文、日本語、한국어。`zh-Hant` 使用通用繁体用词，不单独适配台湾或香港。代码区分大小写、明确指定；不支持别名及系统语言自动识别。

新增语言时，在 `languages.json` 追加代码和原生名称，添加 `locales/<code>.json`，然后执行下方生成命令。注册表必须与发现的资源包完全对应，英文排在第一位。选择器、CLI 选项、协议枚举、搜索与安装后向导无需修改业务代码。生成文件提交入库并由 CI 校验，运行时不扫描目录发现语言。

每套注册语言必须具有与英文完全相同的消息键。`--coverage` 只输出缺失键报告，不写文件；生成和 `--check` 拒绝缺译、多余／重复键、非空消息的空翻译、不安全文本及占位符差异。覆盖率表示键完整性，不代表母语人工审校。运行时对缺失键或内部未知语言保留英文回退；显式配置写入拒绝不支持的语言。

使用语义键和 `{path}`、`{count}` 等命名占位符。所有语言的占位符集合必须一致，但顺序可以改变。禁止位置参数、属性／索引访问、格式说明和转换。状态栏消息必须是单行终端安全文本，标签与枚举值不得包含占位符。翻译完整短语，保留命令、ID、用户文本和技术单位，不引入运行时翻译服务依赖。

## 范围与持久化

界面语言覆盖菜单、目录说明、表单、选项、帮助、进度和恢复消息。`Message` 保留兼容英文的诊断字符串与 `{key, params, fallback}` 协议表示；在 UI 边界按明确语言展示，嵌套错误也保留元数据。业务判断使用稳定代码，不依赖翻译文本；外部错误细节保持原文。

`statusline-ui.json` 继续使用 schema v1。读取无副作用，损坏偏好返回英文及警告；显式写入使用锁、备份及原子替换，并保护未来 schema。界面语言切换立即保存，保留页面、选中项、搜索、输入和草稿，重新绘制字符单元格。写入失败保留原语言。其他窗口在重开／重新加载时读取偏好，不后台轮询。

输出语言独立、默认英文，保存在显示 schema v8。预览跟随草稿变化，正常保存／取消控制持久化。编辑器协议 v11 从注册表生成两种语言类型及允许值，并拒绝旧前端；可移植格式 v1 与运行协议 v2 独立。降级到不支持所选语言的版本前，将两种语言重置为英文并重新安装匹配的原生资源。

## 项目分级搜索

两个编辑器预建所有注册语言的名称、说明和分类索引，加上 ID 与自定义标签。字段保存规范化文本和原始码点位置；查询时不重新翻译或读取语言资源，修改自定义标签仅刷新对应缓存字段。界面切换继续使用同一份多语言索引。

排名保持精确、前缀、英文单词首字母缩写、连续子串、有序子序列，同级保持原顺序。两端按码点执行 NFKD、小写及 Unicode 空白折叠。共享测试包含繁体中文、假名宽度／组合标记及韩文。高亮真实匹配文字，跨语言命中显示原始证据；分类／查询筛选保留既有排序保护、选择和草稿行为。

生成精确宿主版本的声明，检查两个 Mod 的类型并运行官方测试。覆盖 25 种界面／输出语言组合、正反切换、保存／取消／重开、失败写入、导入导出和升级保留。检查原生 32×12、外部 64×18 最小视口，以及常见／缩放视口、长文案、Unicode 和浅深背景。检查安装后 wheel 的 PTY 采集，记录软件包、源提交、宿主和视口；区分 CI、代理检查与人工或 Windows／macOS 终端验收。遵循[测试说明](testing.zh-CN.md)和[发布门槛](../RELEASING.zh-CN.md)。

## 状态栏展示

只有 `statusline.*` 消息生成到独立 Python 语言模块。渲染首次使用时加载所选语言，仅需要回退时加载英文；不解析界面 JSON，也不读取界面偏好。界面缓存覆盖注册语言，内部未知语言在进入缓存前归一到英文。

生产与预览格式化明确传递输出语言，在展示边界翻译已知枚举，保留原始观测、数字、单位、ID 与用户标签。修饰使用所属前缀元数据，不以任意文本识别标签；保留现有英文状态栏输出字节。使用固定源码比较冷／热启动、渲染及搜索，分别记录资源体积和持续刷新成本。

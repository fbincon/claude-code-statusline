# 按影响检查与维护证据

[English](impact-checks.md) | **简体中文**

## 分阶段启用

兼容层通过完整 PR 矩阵和独立校验的 main 晋升后，现已启用专项调度。必需检查按影响计划执行。本次迁移不创建产品版本、发布标签、npm 发布，也不修改已安装产品。

必需检查名称继续为 **Complete candidate evidence**。它表示受保护的汇总门禁，不表示每条路线都执行过完整产品矩阵。汇总门禁核验对应路线的必需作业和有意跳过项。草稿和手动诊断不能生成可晋升验收。

## 职责与检查

分类器读取两个固定 Git 树，包含新增、删除、文件模式和重命名两侧，不依赖 PR 标题、标签或维护者的口头判断。核心行为覆盖 CLI、平台副作用、外部编辑器、Mods，以及 `packages/core`。

| 职责 | 必需检查 |
| --- | --- |
| 维护中的文档和社区模板 | 链接、锚点、双语对应、模板结构和空白错误 |
| 文档媒体与 JSON 记录 | 文件引用、媒体封装、PNG CRC／解压／尺寸及可核验的截图摘要 |
| 译文值、帮助文字值字段和已登记主题颜色 | 消息键／占位符、精确资源生成、相关核心／CLI／TUI 测试、适用 Native 宿主测试与打包／安装检查 |
| 测试及共享夹具 | 已登记的消费测试族及适用平台／宿主组合 |
| 检查、工作流、Action 和发布策略 | 工作流身份与检查／发布契约测试，包含失败场景 |
| 基准、验收及开发工具 | 工具测试族和相关系统检查 |
| 构建／生成输入、开发依赖及导出设置 | 实际包内容比较、生成／构建测试和三平台安装 smoke |
| 产品逻辑、协议、运行依赖及内置技能指令 | 现有完整产品矩阵 |

文档检查运行于 Linux。纯核心测试默认运行于 Linux；平台、应用、终端和工具测试族保留 Linux、Windows、macOS 执行。Mod 检查使用受影响 Mod 的现有固定宿主清单；不支持 Runtime 的宿主被排除，不报告通过。专项宿主作业执行官方校验／测试和可获得的精确宿主声明检查，不连带执行无关的安装／运行时矩阵。Claude 2.1.296 既有声明缺口继续明确保留。

多个类别合并检查清单。未知职责、不支持的文件类型、含义不明的文件模式或无法读取的修订均阻断并报告分类问题，不会自动选择昂贵的完整产品矩阵。冻结归档的改动仍须通过归档完整性检查。

产品静态导入关系优先于测试／工具／文档目录标签，包含被内联的编译期输入；这些改动须比较实际包内容。生成夹具始终选择生成检查。workspace 描述性元数据可单独比较，但不忽略入口、依赖或可执行包契约。未复用证据的批量推送检查实际推送范围，较早的核心改动不能被最后一次文档提交掩盖。

只有保留既有消息键／占位符的译文、已登记帮助文字字面值字段和主题值字段属于展示数据。帮助命令选择器、属性键、控制流、可执行表达式和终端控制字符仍参与比较。语言注册、消息键或默认行为变化仍属于产品改动。生成副本必须与规范源精确一致。产品 `SKILL.md` 属于执行指令，不是普通文档。注释、格式和纯类型改动须证明输出操作等价，并进行实际包内容比较。

依赖分类从四个业务 workspace 追踪运行依赖闭包，包含可选依赖及链接 workspace 的依赖。锁文件中的 `dev` 标记不能单独将运行依赖排除。

## 本地接口

使用固定且已提交的输入。未显式传入 `--compare` 时，规划器只读源码：

```bash
npm run ci:plan -- --base origin/main --head HEAD --output /tmp/impact-plan.json
```

版本化 `ImpactPlan` 记录 base／head／tree 身份、分类器摘要、逐文件原因、选中检查、具体任务及路线：`maintenance`、`product`、`compare` 或 `blocked`。`compare` 表示尚未完成判断，不能生成通过的专项回执。

涉及包内容的改动使用新输出路径完成比较：

```bash
npm run ci:plan -- --base origin/main --head HEAD --compare --output /tmp/impact-compared.json
npm run ci:check -- --plan /tmp/impact-compared.json --task linux \
  --artifact /tmp/impact-compared.json.package/head.tgz --report /tmp/impact-linux.json
```

不涉及打包的计划省略 `--artifact`。使用计划中的任务 ID 和实际平台；Linux 执行不能出具 Windows／macOS 回执。本地回执没有 Actions 执行身份，不能替代 CI 验收。每次使用新报告路径。完整本地 `npm run check` 仍可使用，兼容层验证和核心改动仍要求执行。

包内容比较独立导出两个源码，在禁用生命周期脚本的情况下安装锁定依赖，完成构建、生成校验和打包。比较运行成员及模式，只允许已登记的文档、编译元数据、版本身份和展示差异。运行表达式、入口、依赖及未登记成员仍参与比较，不改写任何包的提交身份或原始字节。比较错误阻断；运行内容不等价时选择完整产品验收。

## 证据与晋升

原有 `ci-evidence.json`、`sourceHashes()` 和 `policyDigest()` 契约保持历史含义。独立的 `ci-maintenance` 信封记录检查计划、实际专项回执、原始产物身份及产品基线祖先引用，不宣称重新执行了完整矩阵。回执绑定精确提交、计划、目标、检查、运行时、Actions run／attempt 和执行时间。产物选择保留最新产物和最新适用运行规则。

正常且内容等价的双父 main 合并复用最终 PR 的维护证据。实际已接受的第一父提交将自身校验器导出到隔离目录，并安装该父提交按完整性摘要锁定的解析器／归档依赖。该代码重新核验源码、合并、检查和包内容比较；不会在校验器上恢复当前候选编译输出。基线／树变化或不支持的集成关系不能借用旧回执，须重新分类并检查实际 main 差异。来源歧义阻断。

普通维护不会仅为了更新文档或工具而下载旧产品候选。发布复用沿维护祖先记录找到仍可用的完整产品基线。所有必需信封、原始执行和产物必须有效；过期、损坏、缺失证据或最新失败运行均阻断复用，不能以较早绿灯或手动诊断替代。现有 30 天证据保留期不变。

维护源码上的标签构建属于**当前源码自身**的包、源码归档、manifest 和校验和。两次独立构建及源码归档重建必须一致。Linux／Windows／macOS 安装 smoke 验证这些新字节。已经验收的第一父 main 校验器独立比较新旧运行内容，并单独校验当前源码绑定的发布授权。发布选择／关联 schema 2 将该校验器 commit／run 与原完整产品验收分开记录，使已验证的策略维护无需重跑产品矩阵，也不改写历史逐源码输入摘要。`ci-release-binding` 分别记录本次检查与原产品覆盖，保留不同源码／包身份。npm 解析该关联，只发布经过验证的当前标签包。标签、包源码和 OIDC provenance 必须一致。

现有完整源码标签和历史 npm 发布继续使用原读取流程。不为测试新路线而移动已发布标签或替换产物。dry-run 检查准备过程与字节，不能证明新版本已发布或新的可信发布者绑定已验证。

## 验证与维护

回归覆盖真实 PR #181 的 PNG／JSON 变更集、混合维护、产品改动、依赖闭包、重命名、未知文件、跳过／草稿作业、包内容等价、不可变基线执行，以及“完整基线 → 多次维护 → tag/npm”来源链。故障场景包含最新失败运行、过期或损坏产物、错误源码身份及缺失的已选择发布证据。

在作业摘要和交付记录中保留路由决定及原始执行身份，观察实际执行量与耗时；复用回执不是新样本。如需回滚，通过正常评审 PR 回退调度，保留证据读取能力和既有发布身份。另见 [CI 维护](ci-maintenance.zh-CN.md)、[测试](testing.zh-CN.md)及[发布准备](../RELEASING.zh-CN.md)。

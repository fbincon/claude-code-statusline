# v1.13.0 多语言性能

[English](performance-v1.13.0.md) | **简体中文**

新增三套完整语言资源后，默认英文／简体中文状态栏进程的热启动耗时未超过多轮噪声筛查边界。编辑器存在实际成本：Python 索引预建约 10 ms，原生翻译／搜索模块导入约增加 19 ms，五语言查询比两语言约增加 0.4–0.5 ms。这些成本予以保留，不声称零开销；同样只保留两种语言的新实现，预建后的查询比原两语言实现更快。

## 方法与边界

2026-10-11 在 Linux x86_64、Python 3.14.4、Node v22.23.2 上测量。基线为 v1.12.0（`ee28dec10a07a1f175d11895f0afe7fb56e8752b`），运行时代码候选为 `1134aee5425ed50fa0ca936321abb246e011b6b0`。从固定 Git 提交导出源码，每批结束复核内容摘要；后续修改仅增加验证工具、测试和文档，被测运行时文件保持不变。

每种模式交替运行三轮，每项 30 个独立进程样本，共 3,600 个热样本与 3,240 个修正后的冷样本。表格为三轮 P50/P95 的中位数，时间单位 ms。`*` 沿用既有复核规则：候选每轮的 P50 或 P95 都更慢，且中位差超过基线相应轮间范围（至少 0.0001 ms）。这是噪声筛查，不是统计置信区间。操作系统文件缓存和 CPU 调度不受控，本地数据不代表跨平台保证。

热模式在计时外预热隔离的字节码缓存。最初报告的冷模式错误复用了热缓存，这部分数据**废弃**。修正后冷进程使用独立空字节码目录，禁止写入并断言目录不存在，因此包含标准库字节码重新编译，而非只冷载入项目文件。下方冷数据只取修正报告。计时轮次不与构建或测试套件重叠。

CLI 渲染使用固定 120 列样本、上下文项和一个代理；英／简中主行与子代理输出 SHA256 与基线一致。单条查找微测约 0.4–0.5 μs，原始值保留在报告中。搜索对英文、两种中文、日语、韩语和稳定 ID 执行 24 次查询，新语言因此带来额外匹配；candidate-2 控制组分离实现变化与新增工作。Python 搜索进程总耗时包括准备及全部 24 次查询；Node 测的是 TypeScript 翻译／搜索模块加载与查询，**不是完整 Claude Client 启动**。

## 搜索与资源规模

十语言夹具将英文复制为 qaa–qae，仅测资源规模，不进入发行物。相同字符串可能共享存储，压缩效果也与真实新增翻译不同。二／十语言控制组使用临时注册及生成资源。

表中 wheel 从固定源码独立构建，临时变体同步重新生成界面协议；不包含后续仅文档修改，正式发布构建会再次比较 wheel 运行时内容。Python／原生资源列为源码字节数，gzip 体积及逐进程原始值见凭据。Python 内存使用 `/proc/self/status` 的 `VmHWM`，每操作／变体 30 个进程，共 360 次探测。计时脚本中的 Python `getrusage` 继承了父进程 RSS 高水位，不能用于判断 Python 内存差异；Node 使用自身记录的进程峰值。内存探测和构建独立于计时执行。

wheel 从 469,234 增至 638,606 字节，增加 169,372 字节，约 36%。四组默认 Python 渲染的映射内存均约 22.55 MiB，五语言搜索相对基线约增加 1.34 MiB；原生模块／搜索进程峰值约增加 10.3 MiB。这是隔离进程测量，不是完整 Claude 宿主内存。主／子状态栏只导入当前语言的生成模块，该路径不读取界面 JSON。
